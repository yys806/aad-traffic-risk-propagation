## 二、−1.4×10⁹ 的根因（已查清并修正）

**根因**：时间前瞻项 `s_pr = s_est − T′·Δv`。当接近速度大于 `s/T′` 时 `s_pr` 变负，
代码把间距下界压到 1e-3 m，交互项 `−a(s*/s)²` 于是出现 10⁹ 量级；随后被 `b_max` 外部截断。

**修正（不引入自由参数）**：
- 未来间距不能为负 → `s_pr ≥ 0.1 m`（趋零即「必然追上」）；
- 交互项在公式内部就按「总加速度不低于 −b_max」封顶：`aint ≥ −(b_max + afree)`。

**验证**：修正前后轨迹**完全一致**（seed0：78/80、峰值 7.37、净距 2.46；seed1：80/80、6.51、2.50），
只是请求值从 −1.4×10⁹ 变成 **−9.00**。说明那串天文数字是公式没设边界，物理上一直是「踩到底」。

> 中途曾试过 `s_pr ≥ 0.25·s_est` 这类下界，结果事件从 78/80 掉到 31/80——**那是自己发明的自由度，已废弃**。

## 四、结论

1. **在干沥青实测范围内（8.4–9.5），0.3.5 的结论稳健**：不依赖某一个上限取值。
2. **9.0 的定位**：工程代表值（预先指定），不是实测中位数，不得在论文里写成「中位」或「10 分位」。
3. **湿路（7.8–8.8）与 7.0 压力档尚未在固定判据下重跑**；0.3.6 显示 7.0 时事件腰斩（31–43/80），
   若研究范围扩展到湿路必须单独报。
4. **Markkula 逐车抽样那一档会产生接触**（净距 −4.8~−11.3），只能作为「司机没踩到底」的探索性情景，
   不能当主分析，也不能据此反选上限。
