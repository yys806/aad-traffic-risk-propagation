## 三、这个结果说明什么

1. **SUMO 与纯 Python 内核跑的是同一条轨迹**：速度误差精确为零，位置误差 1.9e-10 m（双精度舍入量级）。
2. **积分器一致**：若 SUMO 用 Euler 而非 ballistic，位置会累积偏差到 0.1 m 量级，实测没有。
3. **粘性、裁剪、插入、跨零都没造成偏差**：全程 2400 步、5 车，无一次异常。

## 四、一个必须记录的修正

初版脚本里，我为了省事在脚本内用速度序列重新积分出位置（`x[k+1]=x[k]+0.5(v[k]+v[k+1])dt`），
这等于在脚本里又实现了一遍积分，**不能算「原件对账」**。已改为让 `hdm_core.run` 直接返回 `hist_x`，
脚本只读不重算。改后结果与初版完全相同（1.855e-10），说明初版的重新积分确实与内核一致——
但**记录必须用改后的版本**，否则证明的是「我的积分和 SUMO 一致」，不是「内核和 SUMO 一致」。

## 五、边界（这个测试没证明什么）

1. **只测了无扰动、无噪声的平衡态匀速**。头车全程 22.10 m/s，车队不动。
   **没有覆盖**：头车急减速、事件触发、DRAC 超阈、有噪声情形。
2. **只测了 5 车、120 s、单车道、无换道**。
3. **开环**：SUMO 不参与动力学，所以它证明的是「积分器与坐标容器等价」，
   **不证明**「把 HDM 接进 SUMO 闭环后也等价」——那需要测试 D。
4. 未测多车同时插入的时序竞争（本测试按下游→上游顺序插入，未做反序对照）。
