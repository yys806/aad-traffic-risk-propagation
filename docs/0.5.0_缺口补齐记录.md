## 二、已补内容（逐项，含代码位置）

### 2.1 硬判据 #1：五环溯源——补齐

**新增 `Message` 载荷类**（`hdm_msg.py`）：
持有 `event_id / t_src / x_src / v_src`，`payload()` 只返回事实字段；
车端策略（`factor=0.70`、`rate=1.0`）单列为 `local_policy`，**不混入载荷**。

**新增 `MsgState.trace()`**：逐车输出五环——
`ring1_event` / `ring2_payload` / `ring3_delivered`（逐车送达时刻）/
`ring4_cap_bind`（逐车控速介入帧数）/ `ring5_action`（逐车动作时刻），另附 `v_cap`、`v_at_delivery`。

**新增硬断言**（`run_050_python.py`）：逐车检查
载荷三字段有限、送达时刻非空、`cap_bind_frames > 0`、动作时刻非空，任一缺失即 `exit(1)`。

**seed0 实测**：载荷 `{event_id:0, t_src:40.25, x_src:5889.56, v_src:21.47}`；
A3 的 20 辆车送达均 40.85 s；`cap_bind_frames` 783–1262 帧不等；`v_cap` 15.08–16.11 m/s。

### 2.2 硬判据 #3：隔离区位置、速度、加速度三者全断言

原稿只断言 `hist_x`。现补 `isolation_maxdiff_v` 与 `isolation_maxdiff_a`，
三者均要求 ≤1e-12。**实测三者全为 0.0。**

### 2.3 硬判据 #6：新旧内核逐元素等价（替代原「只比总数」）

`gate_050_kernel_equiv.py` 改为 **`x0=5000`（与主分析同坐标系）**，
比较旧内核 `hdm_core.py` 与新内核 `hdm_core_v2.py`（消息关闭）在 340 s 下的
`hist_x / hist_v / hist_a / event / max_drac / min_gap`。

**要求全部 0.0 且 event 全等**；小于 1.0 的差值即判失败并 `exit(1)`。

## 三、机制更正（Gemini 审计给出的、比我原稿准确得多的解释）

原稿写「收益传播给未接收车＝区域收益」，是错的。正确的机制分解：

| 臂 | 首波事件 | 队内事件 | 全窗 | 首波占比 |
|---|---|---|---|---|
| A0 | **126.0** | 93.0 | 219.0 | 57.5% |
| A1 | 68.0 | 128.0 | 196.0 | 34.7% |
| A2 | **9.0** | 95.0 | 104.0 | 8.7% |
| A3 | **6.5** | 87.5 | 94.0 | 6.9% |

**策略把「第一次撞上队尾」的首波事件从 126 段打到 6.5–9 段（降 93–95%），
但对进入 3 m/s 拥堵队后的二次止走波几乎无改善（93 → 87.5–95 段）。**

这同时解释了三件事：
1. **为什么峰值 DRAC 几乎不变**：峰值来自队内未受控的 HDM 止走振荡，
   `v_cap=15.5 m/s` 进队后完全失效；
2. **为什么非接收车也降**：单车道不能超车，后车被接收车的 15.5 m/s **机械压速**，
   首波冲击从 `22.1→3.0`（Δv≈19.1）被拆成 `22.1→15.5` 与 `15.5→3.0`（Δv≈12.5）；
3. **为什么延误不增**：头车永久 3.0 m/s 把所有车的末位置钉死。

**这是「移动瓶颈削峰」，不是「远端信息的区域收益」。**
多车道下后车可超车/切入，这个外溢是否保留**未测**。
