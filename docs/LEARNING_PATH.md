# AAD 项目重新上手学习路径

> 目标：让暂时忘记项目细节的研究者，用最短路径重新获得“研究问题—方法—代码—实验—结果—限制”的完整认识。索引负责导航，原始证据负责定论。

## 1. 先用 15 分钟找回研究问题

先读 `RESEARCH_STATUS.md` 的“当前研究问题”和“不能声称”。本项目研究的不是“消息有没有发出去”，而是：来源可追溯的远端风险消息，在普通物理影响到达目标区域以前，被控制器采用后，是否改变目标车辆集合的动作，并进一步改变目标区域总体风险。

请牢记三层差别：消息交付不等于控制器采用；采用不等于动作改变；动作改变也不自动等于区域风险改变。论文主效应必须把这条链逐层证实。

## 2. 用 30 分钟理解核心研究思路

阅读 `METHOD_AND_ALGORITHM_GUIDE.md`，再看 `ARCHITECTURE.md` 的证据流。核心研究思路是先把“尺子、通信边界、现实覆盖、数值正确性”校准清楚，再冻结协议，最后运行核心效应实验。

- E00 证明工程运行和封存链可信。
- E15-A 证明风险尺子和 leader/TTC 是否可信。
- E16-A 说明现实通信数据究竟可观测到哪一层。
- E17-A 防止仿真只覆盖容易成功的现实状态。
- E01 验证公式、路径和离散时间步，并等待科学容差冻结。
- E02 只有在前述 Gate 全部通过后才允许实现和运行。

## 3. 用 45 分钟理解算法原理与方法设计

按 `METHOD_AND_ALGORITHM_GUIDE.md` 的顺序学习：先看 TTC/DRAC 等风险量如何从前后车运动学得到，再看 pNEUMA 为什么必须做地图匹配、同向候选 leader 和人工盲审，最后看 E00 如何区分 source/channel 四格并记录 state、emission、protocol、action、risk 五张表。

遇到公式时先回答三个问题：变量是什么、单位是什么、在代码中由哪个字段产生。不要先背公式。方法设计的关键不是复杂，而是每个科学概念都有可观测字段和拒绝原因。

## 4. 用 30 分钟建立代码地图

先读 `code/README.md`，再按实验进入 `code/src/riskprop/`：

- 正式模块：`sumo_e00.py`、`e15a.py`、`pneuma_mapmatch.py`、`pneuma_qa.py`、`e16a.py`、`e17a.py`、`e01_metrics.py`、`e01_validation.py`、`protocol_lock.py`。
- 命令入口：`code/scripts/`。
- 自动测试：`code/tests/`。
- 历史实现：三个 `legacy/` 目录，只作追溯。
- 本地大产物：`code/outputs/`；Git 内可携带摘要：`evidence/`。

先读测试再改实现。测试展示了字段契约、拒绝条件和边界，比只读函数名更快。

## 5. 用 45 分钟理解实验逻辑

从 `EXPERIMENT_INDEX.md` 逐项读到 `RESULTS_INDEX.md`，再打开每项便携 audit。实验逻辑是严格串联的：上游 Gate 不通过，下游停止；不能通过换指标、挑种子、删失败样本或降低容差继续。

当前实验逻辑的唯一前进点是人工完成 E15-A v5 的 48 条平衡 pilot。人工结果不理想也必须保留；`uncertain` 是有效观察，不是需要清除的错误。

## 6. 用 30 分钟理解结果含义

便携证据已经表明：E00 的工程链可审计，但物理发送路径未接通；NGSIM 能产生 TTC 参考；pNEUMA 候选 leader 尚未人工验证；SPMD RV_RX 只支持接收状态连续性；E17 参考覆盖不完整；E01 技术真值通过但科学容差未冻结。因此 `protocol_lock_allowed=false`、`e02_allowed=false`。

这些结果回答“基础设施和测量是否准备好”，尚不回答“远端信息是否产生了科学主效应”。

## 7. 识别当前问题

当前问题分为三类：

1. 人工输入：pNEUMA Round 1 必须由研究者判读，AI 不能代替。
2. 外部资产：官方 SPMD Packet 访问当前返回 HTTP 403，不能把访问失败解释成 schema 不合格。
3. 科学冻结：pNEUMA Gate、仿真覆盖、E01 容差和样本量未齐全，协议锁与 E02 必须停止。

## 8. 后续研究方向

当前后续研究方向不是自由扩展新算法，而是按已有顺序闭合 Gate：完成人工 pilot；只读统计并由研究者决定是否继续完整 Round 1/2；通过后生成 pNEUMA TTC；补 E17 仿真样本；冻结 E01 容差与样本量；生成不可覆盖的协议锁；然后另行确认 E02 设计。

跨控制器、跨风险类型、通信受损、物理连通、合流、尾部风险和 Stage II 控制优化都已进入阶段计划，但在当前 Gate 之前只是候选方向。

## 9. 每次重新接手的五步检查

1. 运行 `git status --branch --short`，实时取得代码状态，不信旧文档中的瞬时 HEAD。
2. 读 `PROJECT_CONTEXT.md`、`PROJECT_REGISTRY.json` 和 readiness 便携证据。
3. 运行 `python code/scripts/validate_project_docs.py --strict-git` 与证据 `--verify`。
4. 确认当前唯一任务和谁拥有下一决策；涉及科学设计时由研究者确认。
5. 修改后同步注册表、索引、执行记录、证据快照和 CHANGELOG，再运行全量验证。
