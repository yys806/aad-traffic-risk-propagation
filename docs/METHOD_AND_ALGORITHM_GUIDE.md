# AAD 方法与算法通俗指南

> 阅读顺序固定为：解决什么问题 → 直觉 → 为什么需要 → 具体怎么做 → 数学表示 → 代码实现 → 实验影响。本文解释现有设计，不新增研究变量或实验方案。

## 1. 解决什么问题

交通风险会沿车辆相互作用传播。项目想检验：远端风险信息能否比普通物理扰动更早到达另一片区域，并在被控制器真正采用后改变车辆动作和区域风险。困难在于“发出消息”“收到消息”“采用消息”“动作分化”“风险改变”很容易被混为一谈。

## 2. 直觉

把道路想成两条传播通道：一条是拥堵、制动等物理影响沿车流逐车传递；另一条是通信把远端风险提前告诉目标车辆。若通信只是送达但车辆没有采用，它不应被算作有效处理。若车辆采用了但动作没有改变，也不能声称风险变化由消息引起。

因此项目使用四格实验分别控制“源事件是否存在”和“通信通道是否开放”，并对每一步状态留证据。

## 3. 为什么需要分阶段 Gate

如果风险尺子不准、leader 推断错误、通信字段不可观测，或仿真只覆盖少数容易样本，主实验即使出现差异也无法解释。先做 E00/E15-A/E16-A/E17-A/E01，是为了在看主效应以前冻结测量与拒绝规则，防止结果出来后改口径。

## 4. 具体怎么做

### 4.1 风险测量

对同车道同方向的跟驰对，计算净间距、相对接近速度、TTC 和 DRAC。没有可信 leader、车辆未接近或字段缺失时，不用补零伪造观测，而是保留缺失/不适用状态。

### 4.2 pNEUMA leader 构造

pNEUMA 没有可直接信任的 leader 字段。流程是先把轨迹点匹配到道路方向，再在同方向、合理邻域内生成候选 leader，随后由研究者做盲审。人工 Gate 前，候选只叫“候选”，不得写成真值或生成正式 TTC。

### 4.3 四格和消息链

E00 的四格只允许源事件 `s` 和消息通道 `c` 变化。每次运行记录五表：车辆状态、源/排放、消息协议、控制动作、风险。协议表把生成、发送、交付、校验、采用分别记录；动作表再记录动作是否分化。

### 4.4 物理路径与时间顺序

独立分析器只读封存产物和拓扑，判断源扰动的普通物理路径是否已到达目标区域。科学解释要求消息引发的动作变化发生在物理影响到达以前。

### 4.5 现实覆盖和协议锁

E17-A 汇总真实运动学、跟驰和风险参考，后续与仿真比较覆盖。E01 用解析 fixture 和多个时间步检查公式与离散误差。所有 Gate 和科学容差齐全后，才能生成不可覆盖的协议锁；锁前不允许 E02。

## 5. 数学表示

设净间距为 \(g\)，后车速度为 \(v_f\)，前车速度为 \(v_l\)，接近速度为 \(\Delta v=v_f-v_l\)。当 \(\Delta v>0\) 且 \(g>0\) 时：

\[
\mathrm{TTC}=\frac{g}{\Delta v},\qquad
\mathrm{DRAC}=\frac{(\Delta v)^2}{2g}.
\]

TTC 越小通常表示碰撞时间余量越少；DRAC 越大表示避免碰撞所需减速度越强。若条件不满足，代码必须按协议返回不适用状态，而不是把值设为零。

四格可写成 \(Y_{sc}\)，其中 \(s\in\{0,1\}\) 表示源事件，\(c\in\{0,1\}\) 表示通信通道。一个候选交互效应可用差中之差表达：

\[
\Delta_{\mathrm{info}}=(Y_{11}-Y_{10})-(Y_{01}-Y_{00}).
\]

这只是设计中的估计量形式。当前尚未运行 E02，不得把该式写成已有结果。

## 6. 变量与证据层级

- 处理变量：源事件 `s`、通信通道 `c`；E02 冻结前不得私自增加或改义。
- 中间状态：消息生成、发送、交付、校验、采用、动作分化。
- 结果变量：目标区域总体风险及协议中冻结的辅助指标。
- 校准变量：leader、净间距、相对速度、TTC/DRAC、道路方向、现实覆盖。
- 审计变量：运行 ID、seed、代码哈希、配置哈希、数据哈希、拒绝原因、Gate 状态。

文献定义、论文中的操作定义、代码字段、运行时配置和机器验收是不同层。只有这些层一致时，才能说“当前实现并验证”。

## 7. 代码实现

- 风险与预锁验证：`code/src/riskprop/e01_metrics.py`、`e01_validation.py`。

- 真实轨迹与人工 QA：`e15a.py`、`pneuma_mapmatch.py`、`pneuma_qa.py`。

任何行为改变先写失败测试，再做最小实现。科研设计变化则先停下，由研究者确认变量、解释和 Gate。

## 8. 实验影响

当前方法设计带来的直接影响是“宁可停止，也不把不可观测或未验证内容补成结果”：pNEUMA 人工 Gate 未过，所以 TTC 不生成；Packet 数据不可访问，所以丢包和时延不估计；科学容差未冻结，所以协议锁和 E02 不启动。

这不是项目失败，而是可证伪研究的闭环。失败、空效应、外部阻断和 `uncertain` 都应进入证据链。
