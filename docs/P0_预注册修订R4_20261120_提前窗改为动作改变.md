## 一、R3 的逻辑悖论（必须如实记）

R3 §2.1 规定：

> 唯一主结局：目标区域内 DRAC ≥ 3.4 m/s² 的事件数
> （**按无消息参照界定提前窗口**……）

### 1.1 悖论

设源事件发生时刻 `t_src`，无消息参照下物理影响抵达目标区的时刻 `T_phys`。

在 `t < T_phys` 的区间内，**无消息条件下「有源」与「无源」两臂在目标区的交通状态严格相同**
——这是 `T_phys` 的定义本身蕴含的。

因此：
- 源事件在 `[t_src, T_phys)` 内**不可能**制造出任何额外的 DRAC 冲突
- 该区间内的 DRAC 只可能来自**与源无关的背景风险**
- 于是「要求 DRAC 下降发生在这个窗口内」= 要求一个空集上出现差异

### 1.2 实测证据（0.1.7）

| 项 | 实测 |
|---|---|
| 有源 / 无源 峰值 DRAC | 1.805 / 0.096（种子 20261120）；1.779 / 0.056（20261121） |
| 事件数 | **0 / 0** |
| 首差时刻 | **600.1 s**，只涉及 **5 辆车**，全在目标区边界 **24.8 m** 内 |
| 保守计数窗 | `[600.0, 600.0)` = **空** |

**结论：提前窗塌缩为空。** 这正是 §1.1 悖论的第一个分支（目标区离源近，`T_phys` 瞬间触发）。

### 1.3 GPT 第七十九轮的判词

> **0.1.7 的空窗和零事件是两个独立失败。突破 DRAC 上限，只解决后一个。**

## 二、修订内容

### 2.1 核心改动：时间优先性的对象变了

| 版本 | 「必须发生在物理到达前」的是什么 | 后果 |
|---|---|---|
| R3 | **风险下降** | 悖论：到达前无源致风险，窗口为空 |
| **R4** | **动作改变** | 可检验：车可以在波抵达前就开始减速 |

> **修订后的表述**：
> AAD 要证的是「**车辆动作的改变**发生在无消息参照下的物理影响抵达**之前**」，
> 而「**区域风险结局的差异**」在**事前规定的固定随访窗**内比较，
> 该随访窗**可以覆盖到达之后**。

### 2.2 三个必须分开测量的量

| # | 量 | 怎么测 | 不得怎么做 |
|---|---|---|---|
| **1** | **参照物理到达时刻 `T_phys`** | 只用 **S0 / C0（均无报文）** 按预定物理判据确定 | 不得用 S1 自身的到达时刻 |
| **2** | **首次动作差异 `T_action`** | 以 `t_src` 对齐同种子 S1、S0，在**同一仿真时刻**比较**同一预指定车辆**的实际执行动作（施加的纵向控制或实际发起的换道） | 不得以 S0 起刹为零点；不得以 S0 越线为零点；不得事后挑最早有反应的车辆；**不得把首次收包当成首次动作** |
| **3** | **区域风险结局** | DRAC ≥ 3.4 去重事件数，在事前规定的固定随访窗内比较 | 不得在到达前窗口内单独作主结局 |

**提前量定义**：`T_phys − T_action`。
须**预设最小可辨提前量**，避免把同一仿真步内无法排序的动作和到达判成「提前」。

**预必须锁定的四项**：车辆纳入规则、动作差异阈值、持续帧数、
时间戳取**差异起始帧还是确认帧**。

### 2.2b 两处不能混用的判据（GPT 第八十一轮）

- **S0 起刹只是动作轨迹的一部分**，不是 `T_action` 的零点
- **越线只有在预注册中确实代表「源扰动到达目标区」时**，才可用于界定 `T_phys`
- **「后车车头进入 `mid`」是事件归属规则，不能自动充当扰动到达判据**

### 2.3 随访窗的定义（预注册）

> **随访窗 `[t_src, t_src + H]`**，`H` 在**看到任何处理臂结果之前**冻结。
>
> **`H` 的确定办法**（GPT 第八十一轮 P2）：用**不进入正式分析的独立先导种子**跑 S0（必要时配 C0），
> 先写明「队尾消散」的判据与持续时间，再按从 `t_src` 到消散的耗时取上界**并加固定裕量**。
> - 先导样本最大值只是**观测上界**，不是总体上界
> - **仿真结束还没消散的运行不能当作已消散**
> - 冻结前须检查 `H` 能覆盖 `T_phys` 后预定的最短随访时长
> - **须事先写明正式运行覆盖不足时如何报告，不得事后逐种子延窗**

**分段报告（GPT 修正 §2.3 原写法）**：

- **到达前段** `[t_src, T_phys)`：**不是纯背景风险**——若 S1 确实提前改变动作，
  它也可能在 `T_phys` 前改变 DRAC
- **到达后段** `[T_phys, t_src + H)`
- **全程** `[t_src, t_src + H]`：**主结局**

**不得预先断言「到达后段一定是主结局的实质来源」**，两段都写成**分段描述**。

### 2.4 主结局（保持不变的部分）

> **唯一主结局仍是目标区域内 DRAC ≥ 3.4 m/s² 的去重事件数**，
> 覆盖边界内**所有车辆**（不只统计收到报文或改道的车辆）。
> 变化的只有**计数窗口的界定方式**（见 2.3），主结局本身不变。

**DRAC 是交通冲突风险的代理指标，不是事故率。** 即使主结局下降，结论必须限定在这个代理指标上。

## 四、随之必须重新冻结的四项

| # | 项 | 状态 |
|---|---|---|
| 1 | 目标区域的定义与边界 | 沿用 R3（`mid` 边 1898.5 m，按后车车头 `roadID=="mid"` 判归属） |
| 2 | **物理到达时刻 `T_phys` 的判据** | **新增，必须冻结**（见 §2.2 第 1 条） |
| 3 | 事件去重规则 | 沿用 0.2.0 冻结版（同一后车连续超阈，允许最多 3 个有效低于阈值帧） |
| 4 | 主比较：哪两个臂、比什么、怎么判 | **新增，必须冻结**（见下） |

### 4.1 主比较（四组，同种子配对）

| 组 | 源 | 报文 | 作用 |
|---|---|---|---|
| **C0** | 无 | 无 | 基线（`T_phys` 由此臂与 S0 共同界定） |
| **S0** | 有 | 无 | **参照臂**：无消息下的风险，**`T_phys` 只由它和 C0 定** |
| **S1** | 有 | **准确报文** | 处理臂 |
| **S2** | 有 | **晚报文主动对照** | 检验「早发是否有增益」 |

**主比较 = S1 vs S0**（区域 DRAC 事件数差）。

### 4.1b S2 的正确设计（GPT 第八十一轮 P3，已改掉我原来的写法）

**S2 不叫「安慰剂」，叫「晚报文主动对照」。**

- 按每个种子的 S0/C0 **预先算出 `T_phys`**
- 让 S2 在**不早于 `T_phys` 的首个可交付仿真步**收到报文
- S1、S2 **使用同一生成规则与响应策略**；S2 **缓存并交付原始报文**，晚发时**不重算内容**
- 用 **S2/S0** 核实到达前**没有报文诱发的动作差异**
- 报告晚报文**是否仍被接受、是否实际触发动作**——
  若晚报文全因过期被丢弃，S2 就没实现「晚了但仍能触发动作」的对照

**❌ 我原来写的「S2 与 S1 无差异 → 命题塌」必须改掉**（GPT 明确）：
**未检出差异不等于等效**。只有预设了**有实际意义的等效界值**、且置信区间落在界值内，
才支持「早发没有实质增益」。

**S1−S2 检验的是「早交付相对晚交付的增益」**，不能把提前量与
「报文陈旧、接收时交通状态变化」完全拆开。

### 4.1c 判据失败时的正确表述（GPT 明确）

**§2.2 的门槛没过时**，应写成「**不能把风险差异归因于提前动作**」，
**不是**「风险差异本身不可解释」。

**报文内容限制**：只能含**发送时刻可获得**的信息（队尾位置、速度、事件 ID），
不得含未来信息、不得直接下发换道/减速命令。

## 五、R4 不解决什么（明确边界）

1. **不解决「无报文时风险为零」**：若 S0 事件数为 0，则主结局无从下降 → 仍需先解决风险可测性（0.1.9 的天花板问题）
2. **不解决 Krauss 安全约束的解析上界**：那要靠「前车实际减速超过 `apparentDecel`」等破界机制
3. **不改变投稿目标**：研究者 2026-11-20 明确「投稿目标暂时不要改」

**R4 只解决一件事：让「提前」这件事变得可检验。**
