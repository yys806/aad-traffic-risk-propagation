# P3-B 独立块可达性核查（2026-11-18）

## 一、结论

**pNEUMA 在结构上无法满足「≥30 个独立分析块」的预注册要求。因此 B 不能作为 AAD 的正式辅助证据，只能作探索性报告。**

这不是 B 的阴性结果，是数据供给量与预注册要求不匹配。

## 二、核查依据

### 2.1 本地只有一个采集单元

```

  20181101_d1_0800_0830.csv   73.5 MB   ← 唯一完整文件
  _incomplete_downloads\                 ← 只有半截 zip
```

即：1 天 × 1 场 × 1 架无人机 = **1 个采集单元**。

按协议 §2.8 冻结定义（主分析块 = 原始采集单元合并后的记录块），**当前只有 1 块，单块占比 100%**。

### 2.2 官方数据集的最大场次数

Zenodo 记录 `10.5281/zenodo.10491409`（pNEUMA_dataset.zip）的文件清单结构：

- **日期**：20181024、20181029、20181030、20181101 —— **4 天**（官网称「over five days」，但 zip 清单只见 4 天；第 5 天是否单独发布**未核实**）
- **每日场次**：0800–0830、0830–0900、0900–0930、0930–1000、1000–1030 —— **5 场**（20181024 从 0830 开始，仍 5 场）
- **每场无人机**：d1–d10，另有 dX（疑为全场多机合并文件，1.1–2.4 GB，**合并口径未核实**）

**采集场次上限**：

| 算法 | 场次数 |
|---|---|
| 保守（zip 清单实际天数 4 天） | **20** |
| 宽松（官网「5 天」× 5 场） | **25** |

**两种算法都 < 30。**

### 2.3 为什么不能按「每架无人机一块」拆

协议 §2.8 与 GPT 第七轮均明确：

> 视野不重叠，不等于交通过程独立。若相邻路段由同一车流贯通，换了无人机仍不应拆块。

10 架无人机悬停在**同一个 1.3 km² 中心商务区**的不同位置，覆盖约 100 个路口、100 km 车道。区域内车流贯通，无法论证各机覆盖的交通过程相互独立。

**结论：块数上限 = 采集场次数 ≤ 25 < 30。**

### 2.4 官方 README 另外两条限制

- 存在无数据时段，原因「某架无人机停止录制」（该机数据缺失，其他机继续）
- 部分轨迹偏离路网：多为摩托车行驶于步行街，或无人机移动导致地理配准质量下降（官方举例 `20181024_d4_0830_0900.csv`）

## 三、处置（按 GPT 第七轮判定）

1. **不下载其余场次**。既然上限 < 30，补采无法使正式分析成立。
2. **B 降为探索性分析**，报告措辞按 GPT 给定：

> 本地数据按预注册的采集单元合并规则仅形成 1 个主分析块，单块占比为 100%，未达到至少 30 块且单块占比不超过 20% 的要求。因此，预注册主分析不可评估；下述 B 结果仅作探索性报告，不作为 AAD 的正式辅助证据。

3. **不修改切块方式补数**。协议 §5 已禁止降强度、缩提前量、把事件或帧当独立块。

## 四、若要让 B 成为正式证据，只有两条路（待研究者决定）
