## 零、这份协议为什么存在

本课题在 2026-11-18 查出一处测量错误：pNEUMA 的 `speed` 字段单位是 **km/h**，此前整条分析链按 m/s 使用，导致所有速度与加速度数值放大 3.6 倍。该错误连带推翻了急刹门槛、事件队列与多个下游结论。

教训不是「修掉这个 bug」，而是：**此前的工作方式是一边做一边撞 bug。** 本协议的目的，是把「数据前提」和「判定规则」在动手之前全部写死，使下一步先看依赖是否通过，而不是看到结果异常才回头猜是哪一列读错了。

因此本协议分两部分：**第一部分是数据契约**（这份数据每一个字段是什么、单位是什么、什么是假设），**第二部分是分析协议**（研究问题、信息集、事件定义、判据、继续与停止条件）。

### 1.12 官方 README 确认与修正（2026-11-18 读取本地 README.html）

**确认了我的判断**：
- 「Speed is in km/h」→ `speed` 与 `avg_speed` 均为 km/h ✓
- 「distance traveled in meters」→ `traveled_d` 为米 ✓
- 「Longitudinal and Lateral Acceleration in m/sec²」→ `lon_acc`/`lat_acc` 是**纵向/横向**加速度，**不是经向/纬向**（此前「未核实」，现已确认）
- 有一只无人机是 23.97 FPS 而非 25 FPS，官方建议重采样

**修正了我的错误假设（此前全错）**：

| 车型 | 我之前假设 | **官方值** | 偏差 |
|---|---|---|---|
| Car / Taxi | 4.5 m | **5.00 m** | −0.5 m |
| Motorcycle | 2.0 m | **2.50 m** | −0.5 m |
| Medium Vehicle | 6.0 m | **5.83 m** | +0.17 m |
| Bus | 12.0 m | **12.5 m** | −0.5 m |
| Heavy Vehicle | 12.5 m | **12.5 m** | 0 |

**含义**：两车净距 = 中心距 −（本车长 + 前车长）/2。此前用 4.5 而非 5.0，每对汽车净距**多算了 0.5 m**；摩托车对多算 0.5 m。所有已产出的净距数值需按官方车长重算。

**另外两条限制（官方原文）**：
- 数据中存在无数据时段，原因是「某架无人机停止录制」——本文件之所以步长全为 0.04 s，可能因为它是单机记录且该机全程正常
- 部分轨迹偏离路网，多为摩托车行驶于步行街，或无人机移动导致地理配准质量下降

### 1.4 硬约束

1. **先判连续段，再求导。** 跨长缺口算出的加速度是「缺口两端的平均变化」，不得当作缺口内某帧的减速证据。禁止「删 NaN 后用固定 dt」求导。
2. **按六字段块解析**，不按绝对列号猜字段。
3. 负净距保留为诊断值，不截为零。
4. 未使用车宽，不得宣称做了车身外廓重叠判定。
5. 🔴 **加速度只能从 `speed` 字段求导，禁止从位置二阶差分求导。**（2026-11-18 审计实测，见 1.6）
6. 🔴 **`speed` 是平滑派生量，求导窗口必须在看结果前冻结。** 窗口不同会改变减速度峰值，不得事后挑选。
7. 🔴🔴 **`speed` 字段不是实时可得的，预测器输入禁止使用它。**（2026-11-18 实测，见 1.11）

### 1.11 🔴 决定性发现：`speed` 用了未来帧（2026-11-18）

**检验方法**：位置量化 8.8 cm，在 1.0 s 窗下速度不确定度仅 0.088 m/s（可忽略）。据此由位置重建三种 1.0 s 平均速度，与 `speed` 比对。

**检验一：与三种位置速度的 Spearman 相关（244 辆车，逐车取中位）**

| 速度重建方式 | 用到的帧 | Spearman | RMSE |
|---|---|---|---|
| 后向（只用过去） | t−1.0 … t | 0.9816 | 0.381 m/s |
| 前向（只用未来） | t … t+1.0 | 0.9816 | 0.376 m/s |
| **居中（前后各半）** | t−0.5 … t+0.5 | **0.9977** | **0.273 m/s** |

**检验二：减速起点对齐（208 次明显减速，降幅 ≥ 2 m/s）**

`speed` 下跌时刻 − 后向位置速度下跌时刻 = 中位 **+0.560 s**，p25 +0.520、p75 +0.680；领先 > 0.1 s 占 **95.2%**，滞后 > 0.1 s 占 2.4%。

**结论**：`speed` 是以约 1.1 s 居中窗口平滑得到的派生量，**内置约 0.56 s 的未来信息**。

**后果（必须写进论文限制）**：主问题的门槛是「在本车减速起点前 1.0 s 预警」。若预测器使用官方 `speed`，其中约 0.56 s 来自数据本身的前视，**1.0 s 门槛的一半以上是数据造出来的，不是预测能力**。

**因此冻结两条**：

1. **标签可用 `speed`**（离线判定减速起点，允许用未来帧）。
2. **预测器（S 与 L）的全部输入速度必须由位置后向差分重建，不得读 `speed` 字段。** 位置在 0.48 s 后向窗下速度不确定度约 0.18 m/s，可用。

**这条同时意味着**：任何基于官方 `speed` 得到的「提前量」数值，一律不得作为实时预警能力的证据。

### 1.6 审计实测：两条决定方法的事实（2026-11-18）

**事实一：位置量化精度约 8.8 cm（经度）/ 11.1 cm（纬度）。**

经度最小非零步进中位 1.0e-6 度。在 dt = 0.04 s 下：

| 由位置差分求什么 | 不确定度 |
|---|---|
| 速度（一阶差分） | ≈ **2.19 m/s** |
| 加速度（二阶差分） | ≈ **54.8 m/s²** |

**位置差分不能用于加速度。** 此前出现的 −67.9 m/s² 等荒谬值，根因在此（不只是单位错）。

**事实二：`speed` 字段是高度平滑的派生量。**

- 逐帧加速度变化的绝对值中位仅 **0.010 m/s²**（若为原始未平滑观测，该值应 > 2）
- 用 1 s 长窗核对：`speed/(位移/时长)` 中位 **1.003**，p10–p90 = 1.002–1.004 → **与位置完全自洽**

**结论**：`speed` 在单位换算（÷3.6）后可直接作为速度真值使用；加速度须由它求导，且求导方式（窗口/阶次/是否再平滑）属于**必须预注册的方法参数**。

## 二、分析协议

### 2.1 定位

P3-B 是 **AAD 的辅助证据**，不是 AAD 主命题的验证。主命题（可追溯消息改变区域风险）标注为「**核心因果命题尚未评估**」。

理由：现有 pNEUMA 是无干预的自然轨迹，既没有消息生成/交付记录，也没有可信反事实，因此不能识别「消息改变行为」或「风险下降」。

### 2.2 主问题

> 在低速城市走停中，相比**只使用本车截至当时的运动历史**，加入**几何前车截至当时的运动信息**，能否在**相同误报预算**下，提高「**至少在本车减速起点前 1.0 s** 发出预警」的事件比例？

- 终点 = **本车减速起点**（不是达到强度阈值的时刻，不是前车减速起点，不是队列停下时刻）
- 「提前于」必须严格按此定义；只比「本车已明显减速才报警」更早，不算增益

### 2.3 信息集（三层）

| 集 | 允许使用 | 回答 |
|---|---|---|
| **S** | 本车速度、加速度及其历史 | 本车自身能预告多少 |
| **L** | S + 几何前车车距、相对速度、仅用当时与过去观测可估的前车减速度 | 前车信息相对本车历史增加多少（**主比较 L vs S**） |
| **R** | L + 该时刻确实可交付、且不属于 L 的信息（更上游车辆状态，或带独立时间戳的前车直传状态） | 相对本地感知还有无额外价值（更贴近 A 的比较 R vs L） |

**命名纪律**：L 只能叫「**本地前车信息代理**」，不得叫「驾驶员或雷达实际看到了什么」——轨迹数据无视距、无遮挡、无传感记录。

**概念纪律**：光速传递的是观测信号；沿车队传播的是车辆运动扰动。AAD 比较的是消息**可用**时刻与扰动**到达**时刻，不是无线电与光谁更快。

### 2.4 三个时间量（不得混用）

| 量 | 定义 | 用途 |
|---|---|---|
| **绝对提前量** | 本车减速起点 − 预警实际可用时刻 | **主判据**：是否达到 1.0 s |
| **相对提前增益** | 同一事件上，基线预警时刻 − 增强组预警时刻 | 共同命中事件里早了多少；不能单独用于评价（两组可能漏掉不同事件） |
| **前后车起点时差** | 本车减速起点 − 几何前车减速起点 | 描述场景可利用的时间尺度；**不是人的反应时间**，不用于反推主门槛 |

### 2.5 主门槛与敏感性

- **主门槛 1.0 s，冻结。** 名称：「有物理尺度解释的预警评价门槛」。不得称「已证实能改变驾驶行为的最低时间」。
- 固定另报 **0.5 s 与 1.5 s** 敏感性结果。**不因审计结果改主门槛。**
- 1.0 s 的物理依据（时间预算）：若目标是以 1 m/s² 减速度多降低 1 m/s 车速，仅执行就需约 1 s，尚不含响应与执行建立时间。这证明 1 s 对低速纵向运动不是无尺度数字，**不证明 1 s 足够完成某项干预**。
- 人类反应时间 1–1.5 s 作为本场景适用值：**未核实**，不作为门槛依据。

### 2.6 事件定义（冻结第一版）

| 项 | 规定 |
|---|---|
| 主事件强度门槛 | **1.0 m/s²**（轨迹估计减速度），另报 1.5、2.0 m/s² 下的过程数 |
| 起点 | 用预登记的**持续减速规则回标到过程开始**，不取强度门槛的穿越时刻 |
| 分析单位 | **一次可辨认的减速过程**；极端单帧只用于描述强度或查测量异常；连续过阈值段只描述过程中的强减速部分 |
| 预警目标窗 | 未来 **3 s** |
| 同一过程 | 只记**一次**命中；重复报警合并规则预先冻结 |
| 晚报 | 窗内确有事件但提前不足 1 s → 记**晚报**，不算达标命中，也不冒充误报 |
| 停车后等待与重新起步 | 不计入该次减速过程 |
| 轨迹在过程结束前截断 | 不得当作完整过程 |

**必须一并写入登记表的配套参数**：低速上限、持续时间下限、相邻过程合并规则、所需历史窗长度。

### 2.7 主比较与误报预算

- 在相同 **5 次误报 / 可评估车辆小时**预算处，比较两组「至少提前 1.0 s 的事件比例」。
- 该预算是**研究比较点**，不是可部署的误报标准。
- 主分母 = 共同可评估的**全部**目标事件（**漏报也在分母里**）。
- 并报：0.5 / 1.0 / 1.5 s 达标比例、绝对提前量、共同命中事件的配对时差。
- 若用留出集估计匹配误报预算的性能曲线，那是性能评估；**部署阈值必须另在校准集定**，不得从测试集挑。

### 2.8 依赖结构

- **按本车减速过程评分，按队列波或更粗的记录块切分、重采样、算区间。**
- 一个波里十辆车可贡献十次预测机会，**不得当作十次独立验证**。
- 波的划分规则（预先规定）：同一车道或连续跟驰链上，按相邻车辆关系、减速起点时空顺序、预先冻结的传播相容范围连成候选波；前车更换、轨迹缺失、相邻波无法区分时标为不确定。
- 推断时**宁可把可能相关的候选波放进同一记录块，也不要为增加波数硬拆**。
- 开发、校准、测试**不得共享同一依赖块**。
- 必报：事件数、车辆数、候选波数、最终分析块数、最大块占比。
- 设计效应可作补充，**不代替按块推断**。

### 2.9 减速原因的处理

- 保留「**原因未知**」，允许「与前车响应相容」「与信号或队列传播相容」并存。
- 停止线附近聚集、沿转弯路径减速、多车依次降速形成传播序列，都只是**情境证据**，不是互斥的原因标签。
- **不得**把「时序与几何上相容」升级为「已确认由前车引起」。
- **不因原因未知而剔除主分析事件**——原因未知的本车减速仍是主预测任务的有效事件。

## 三、可行性审计：六张归档表

| 表 | 必报字段 |
|---|---|
| **1. 数据与计时** | 记录时长、采样间隔与缺帧、跨车同步、轨迹处理是否用了未来帧、起点对标注规则的敏感性；分别记录「状态发生时刻」与「预测时可用时刻」 |
| **2. 减速事件** | 轨迹估计的减速度分布（按车辆等权 + 按过程统计）；各强度门槛的过程数、持续时间、速度变化、受影响车辆数。无独立真值时**不写「真实减速度」**，写「轨迹估计减速度」 |
| **3. 信息覆盖与样本流失** | 候选事件 → 可判定起点 → 有完整前窗 → S/L 均可评估；逐步列分子分母与前车丢失、换车、截断等原因。若做 R，另报 R 覆盖与可用时间戳 |
| **4. 误报背景** | 同一低速适用范围、同一信息覆盖规则下，可评分但预警窗内无目标事件的**连续车辆小时**；记录边界与未来窗口不完整的删失。**不能只抽事件前窗** |
| **5. 依赖结构** | 事件、车辆、候选波、最终分析块；各块事件数与背景时长；最大块占比；按块划分后各集合规模 |
| **6. 前后车时序** | 起点时差分布、负时差与不可配对比例；标签「与跟驰传播相容」「存在可见竞争解释」「无法判读」。标签用于解释，不替代因果识别，不筛掉未知原因事件 |

## 四、继续条件（三条全过才继续）

### 条件一：计时质量

- S、L 的输入能**按时点重建，不用未来信息**
- 同步与起点标注的不确定性**足以分辨 1.0 s 门槛**
- 冻结 **0.25 s** 为计时质量容限，并在审计报告里说明它是**可验证的误差界**还是**仅为标注敏感性**——两者不得混写

### 条件二：样本量（留出测试部分）

| 项 | 下限 |
|---|---|
| 独立分析块 | ≥ **30** |
| 可评分主事件 | ≥ **100** |
| 无目标事件的可评分车辆小时 | ≥ **20** |
| 单块占比 | ≤ 测试事件数或背景时长的 **20%** |
| 独立开发与校准数据 | 必须有 |

### 条件三：精度规划

- 按**实际块规模**与**预先声明的保守相关性**做精度规划
- 主比较的比例差：计划 **95% 区间半宽 ≤ 10 个百分点**
- 误报预算处有足够背景可估计
- **数量下限只是筛查，不能替代精度规划**

## 五、停止条件

任一继续条件失败，写：

> **在预注册的信息集、提前量及误报预算下，本数据不可评估。**

并列出失败项。

**禁止**：降强度、缩提前量、把事件或帧当独立块来补数。

**例外**：若只是缺少验证真实传感可用性的资料，可保留明确标注的「轨迹代理」结论，但不得升级为真实感知或消息优势。

**反向要求**：若审计通过而后续结果没有优势，应报告「**在该比较下未建立预测增益**」及其区间，**不是**回头宣布数据不可评估。

## 六、本协议与 AAD 主线的关系

| 层次 | 状态 |
|---|---|
| **A 主命题**（可追溯消息改变区域风险） | **核心因果命题尚未评估**。需要：可追溯的消息生成/交付/响应记录 + 独立定义的物理到达与区域风险指标 + 可信反事实 |
| **R vs L** | 若取得可信消息可用时间戳与独立定义的扰动到达时刻，可检验 A 的**一个必要条件**：远端消息能否在物理影响到达前提供本地尚无的信息。仍不证明接收方行动或风险下降 |
| **L vs S**（B 主比较） | 若为正，只证明直接前车含有本车历史之外的、可在减速起点前利用的预测信息。不证明远端消息比本地感知更早，不证明提前知道会让区域更安全 |

**若最终只有 L vs S 而无 R vs L 或消息时序证据**：成果可以成立，但它是**本地交通预测结果**，不是 AAD 主命题的验证。写作时必须如此定位。
