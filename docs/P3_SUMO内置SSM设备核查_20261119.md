# SUMO 自带 SSM 设备：内置 DRAC/TTC/PET，且带检测距离参数（2026-11-19）

阶段：P3 ｜ 主指标实现方式（GPT 第四十三轮 Q1 的自查）
核查方式：`sumo --help` + 实跑对照
脚本：无（一次性的装置验证，记录在此）

---

## 一、发现

SUMO 1.26 自带 **SSM（Surrogate Safety Measures）设备**，命令行参数：

| 参数 | 作用 |
|---|---|
| `--device.ssm.probability` | 给车辆装 SSM 设备的概率 |
| `--device.ssm.measures` | 选指标，可选 `TTC` `DRAC` `PET` `PPET` 等 |
| `--device.ssm.thresholds` | 各指标阈值，按顺序对应 |
| **`--device.ssm.range`** | **检测距离（米）：只有这个距离内的车辆才计算 SSM 值** |
| `--device.ssm.trajectories` | 是否记录完整轨迹 |
| `--device.ssm.mdrac.prt` | MDRAC 的感知反应时间 |
| `--device.ssm.file` | 输出文件 |

另外还有 `--device.toc`（awareness 模型）与 `--device.driverstate`（驾驶员状态模型）。

## 二、实跑验证

装置：前车静止于 x=300，后车从 x=1 以 23.6 m/s 出发，`--device.ssm.measures "TTC DRAC"`、
阈值 `2.0 3.4`、检测距离 100 m。

输出：

```
<maxDRAC time="9.20" position="295.00,0.00" type="2" value="3.62" speed="23.60"/>
```

手算对照：t=9.2 时后车走了 23.6 × 9.2 = 217 m，位置约 218；前车前端在 295；
净距 = 295 − 218 = **77 m**；DRAC = 23.6² / (2 × 77) = **3.62**。

**SUMO 给 3.62，手算 3.62，完全一致。**

=> 内置 SSM 的 DRAC 定义与我用的 `v²/(2g)` **是同一个公式**。

## 三、这对我们意味着什么

**第一，主指标应该改用 SUMO 内置 SSM，不再手算。**

理由：手算的指标要让审稿人相信「你的实现没错」，内置的只需说「用的是 SUMO 官方 SSM 设备」。
而且它同时给 TTC、PET、PPET，可以做多种指标的一致性检验。

**第二，`--device.ssm.range` 不等于「限制驾驶员的视距」。**

它限制的是**测量范围**（只统计这个距离内的冲突），
不改变车辆的跟驰行为——车辆该看见还是会看见。这一点必须写清楚，不能混用。

**第三，SUMO 确实没有「跟驰视距」参数。**

我查遍 `--help`，没有 car-following 层面的感知距离选项。
所以「本地只能看 N 米」这件事，**不能靠配置实现，必须靠自定义控制器或外部干预**。
这正是 GPT 第四十三轮 Q2 要判的两难。
