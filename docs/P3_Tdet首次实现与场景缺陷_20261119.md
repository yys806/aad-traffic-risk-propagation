# P3-T_det 首次实现：标定失败，暴露场景缺陷（2026-11-19）

脚本：`code/scripts/p3_audits/compute_t_det.py` ｜ 产物：`code/outputs/analysis/P3_tdet/tdet.json`

## 一、做了什么

按 GPT 第三十七轮的规则实现了 T_det（本地可用触发时刻）：

- 只在控制采样相位（0.6 s）取样
- 只读三个量：自车速度、与前车净距、闭合速度
- 量程 50 m（仿真假设）
- 阈值在无事件回合标定，不在实验结果上试

## 二、结果：θ = 0.0000，标定退化

| 项 | 结果 |
|---|---|
| 标定集（plain 臂） | 869 辆车有观测 |
| **标定出的阈值 θ** | **0.0000** |
| p50 / p99 | 0.0000 / 0.0000 |
| stop 臂触发 | 869 辆中 637 辆触发（73%） |
| 最早的触发 | V59，t0+1.20 s |
| 误报检查（同一 plain 臂） | 0 辆触发 |

## 三、根因：plain 臂**完全没有速度变化**

```
plain:  p1=30.000  p50=30.000  p99=30.000  std=0.000
        逐车速度 std：中位 0.0000，最大 0.0000
stop :  p1=0.000   p50=0.000   p99=30.000  std=14.612
```

**无源事件的整条路上，每一辆车在每一帧都是精确的 30.000 m/s，零方差。**

原因：整条路是一个**完美均匀的饱和车队**——所有车从同一平衡速度出发、同车头距、
按 Krauss 平衡条件稳态行驶，彼此之间没有任何相对运动。

于是：
- 标定集里根本没有「正常的减速或逼近」可标，θ 只能是 0
- θ=0 意味着任何数值抖动都算越阈 → 触发率 73%，这个触发没有意义

## 四、这不是实现 bug，是场景缺陷

GPT 第三十七轮的原话已经预警过：
> **标定集应包含正常跟驰和通常会出现的减速，而不是只用匀速轨迹。**

我们的场景恰恰是「只用匀速轨迹」。

**三个连带后果：**

1. **T_det 无法标定**，主对照（本地臂）也就无法定义。
2. **场景不真实**：真实交通永远有速度波动（±几 m/s）。一条 15 km 上所有车精确等速，
   是传送带，不是道路。审稿人一定会问这个问题。
3. **「风险」的成因可疑**：现在的危险完全来自「在一个绝对均匀的车流里人为放一辆停住的车」。
   真实道路上的危险有很大一部分来自**本来就不均匀**的车流。

## 五、另一个需要核对的量

当前配置：车头距 40 m、平衡车速 **30 m/s（108 km/h）**。
时间车头距 = 40 / 30 = **1.33 s**。

而高速公路的常规跟驰时距约 2 s（108 km/h 时约 60 m）。**我们的场景比真实高速更激进。**

这条与「0.6 s 动作间隔是否能代表真实驾驶」是同一个问题的两面：
**车头距与动作间隔必须联合标定，不能各自单独选。**

## 六、下一步的三个候选（需要 GPT 判）

**候选 A：给场景加自然的交通异质性。**
- 拉开 speedDev、开启 sigma、随机化发车时刻与位置
- 让车流本身就有扰动，再在这批「正常波动」上标定 T_det
- 代价：需要重跑所有配置；且「异质性多大算真实」要有依据

**候选 B：用 NGSIM 真实数据标定 T_det。**
- 直接从真实轨迹里取速度/净距/闭合速度的分布，定阈值
- 好处：依据是真实数据，正好也能回应「场景是否真实」
- 代价：NGSIM 是高速主线，与我们的单车道排队场景不完全对应

**候选 C：两者都做。**
- 用 NGSIM 定阈值（外部依据），用加异质性的仿真跑实验
- 最慢但最稳

## 七、这次没证明什么

1. **没证明 T_det 不可实现**，只证明**在当前这个理想化场景里无法标定**。
2. **没证明场景一定不真实**，需要与 NGSIM 实测分布比对后才能下结论。
3. **没做留出集误报检验**（标定集=检查集，0% 是乐观估计）。
4. **只测了一个配置**（40 m + 0.6 s）。
