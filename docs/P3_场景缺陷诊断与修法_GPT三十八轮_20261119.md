## 一、GPT 抓到的硬错（我的实现问题）

> 「核对 a⁻ 和 c⁺ 的定义与量纲；**若一个是加速度、一个是速度，不把现有 min 当作同量纲物理分数**，任何换算都记为规则变更。」

**我确实错了**：`m = min(a⁻, c⁺)` 把 **m/s²** 和 **m/s** 放进同一个比较，量纲不一致。
已改为两分支**各自独立**标定：θ_a（单位 m/s²）与 θ_c（单位 m/s）。

**修完结论不变**：plain 臂两分支的 p50 与 p99 仍精确为 0，θ_a = θ_c = 0。
所以这不是实现 bug 造成的，**根因仍是场景零方差**。

## 二、场景的核心缺陷（GPT 判断）

**问题不止「零方差」一个点。** 三个层面都要查：

1. **车头距与车速的组合本身是否代表任何真实道路**
   40 m 车头到车头 @ 30 m/s = THW 1.33 s，比真实高速（约 2 s）激进。
   若组合本身不成立，**加异质性也救不了**。
2. **速度因子是否真的生效**
   plain 臂速度标准差精确为 0，说明 `speedDev=0.12` 在当前设置下**没有产生任何效果**
   （饱和车队里所有车被前车锁死，速度因子失效）。这是要查清的实现问题。
3. **异质性从哪来**
   GPT 明确：**不许为了「让 θ 不为零」去调 speedDev / sigma**，那是凑结果。
   参数要有**实测依据**。

## 三、选路：做 A，但先定场景

三个候选里，GPT 选 **A（加自然交通异质性）**，但加了三个前提：

1. **先明确定义的「目标场景」**，再定参数；不能参数先行。
2. **参数由实测数据约束**（NGSIM 的速度-车头距联合分布），不是试出来的。
3. 加完异质性后，**判定标准必须同步改**：
   无事件臂不再零暴露，准入规则里的「高于配对背景」要改成**多回合配对增量**
   （不是单对 X > Y），否则解释不了统计不确定性。

## 四、不可直接做的事

| 别做 | 原因 |
|---|---|
| 把 40 m 直接改成 60 m（凑 2 s） | 没依据；且会让四个已过门配置全部失效 |
| 为了 θ>0 调 speedDev / sigma | 凑结果 |
| 沿用「有源 vs 无源」单对比较 | 背景不再为零，单对比不出增量 |
| 用标定集自己验证标定集 | 0% 误报是乐观估计 |

## 五、下一步执行顺序（GPT 给的，动作级）

1. **封存旧结果并核口径**（已完成大半）：
   - ✅ 40 m 是**车头到车头**（`pos = 10.0 + headway*i`），净距 35 m，THW = 1.33 s
   - ✅ 量纲错误已修（θ_a / θ_c 分开）
   - ⬜ 速度因子为何没生效 —— 待查
2. **用 NGSIM 量真实 THW 与速度的联合分布** ← 正在跑
3. 按实测分布**定义目标场景**，再定 speedDev / sigma / 发车抖动
4. 重跑无事件臂，确认**有非零背景**且可标定
5. 在无事件回合上标定 θ_a / θ_c，**另用留出回合验证误报**

## 六、这次没证明什么

1. 没证明 T_det 规则本身不可行 —— 只证明当前场景无法标定。
2. 没证明场景一定不代表真实 —— 等 NGSIM 分布比对结果。
3. 没证明 1.33 s 一定是错的 —— 需要先确定「我们要代表哪一类道路工况」。
4. 修了量纲之后，**没有改变任何已有实验结论**，只改变了 T_det 的实现。
