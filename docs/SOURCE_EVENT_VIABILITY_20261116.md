# 自然源事件可行性调研（2026-11-16）

> 问题：AAD 要求「来源可追溯的风险事件」在仿真中自然发生，但 B00/Round2 场景里 Formal A = 0。
> 本文回答：这个 0 是模型能力问题还是设定问题，有哪几条路可以造出合格的自然源事件。
> 依据：仓库既有诊断 + SUMO 官方文档 + SUMO 2026 会议论文（均已实读）。

---

## 一、为什么现在是 0

仓库 2026-10-21 的诊断（`STAGE_0_5_CONDITIONAL_STATE_SUPPORT.md` §7）：

- 真实 NGSIM 里，每小时每辆车有 17–23 次「两秒内会追尾」的连续段。
- 我们的仿真里只有 1 次上下。
- 原因：仿真车流是**一条整齐的、所有人几乎同速的慢行车流**，前后车相对速度接近 0，TTC 这个分数算不出小值。
- 净拉开份额：仿真 0.40–0.43，现实 0.53。

**关键判断**：这不是「参数没调对」，而是**模型里没有产生风险事件的机制**。SUMO 默认的 Krauss 模型按「安全速度」设计，它的目标是永远不撞，所以结构上不会产生接近冲突。

---

## 二、SUMO 官方给出的路线（实读 `sumo.dlr.de/docs/Simulation/Safety.html`）

官方文档有一节专门叫 **「Deliberately causing collisions」**，明确写：可以通过配置让模型「驾驶得更不安全」，以一定概率制造碰撞，或者用车辆停靠强迫意外制动。

它列出的手段分四类：

**A. 跟驰相关**
- `tau` 小于仿真步长 → 车间距被压缩到碰撞
- `tau` 小于 `actionStepLength`
- `apparentDecel` 小于 `decel` → 让后车误判前车制动能力
- `driverstate` 设备（驾驶员不完美）
- EIDM 跟驰模型（原生带驾驶误差参数）
- 关闭插入检查后高速小间距插入

**B. 变道相关**
- `lcSigma`（横向不精确）、`lcPushy`、`lcImpatience`、`lcAssertive`

**C. 交叉口相关**
- `jmDriveAfterRedTime`（闯红灯）、`jmIgnoreFoeProb`（忽略路权车）、`jmTimegapMinor`

**D. 直接干预**
- TraCI `setSpeed` 覆盖速度 + `speedMode` / `laneChangeMode` 关闭安全检查

## 三、两条最值得走的路（都已核实可用）

### 路径 1：driverstate 设备（推荐首选）

**是什么**：SUMO 内置设备，给车辆加 `=driverstate` 即可。它用 Ornstein–Uhlenbeck 过程在「感知层」注入误差——驾驶员看到的车距和速度差有偏差，`awareness` 越低偏差越大；同时 `maximalReactionTime` 会让反应时间随 awareness 下降而变长。

**关键参数**（实读 `sumo.dlr.de/docs/Driver_State.html`）：
| 参数 | 默认 | 作用 |
|---|---|---|
| `initialAwareness` | 1.0 | **必须设小于 1 才有误差**；1.0 表示完美感知 |
| `headwayErrorCoefficient` | 0.75 | 车距感知误差的放大系数 |
| `speedDifferenceErrorCoefficient` | 0.15 | 速度差感知误差系数 |
| `maximalReactionTime` | 原 actionStepLength | awareness 最低时的反应时间 |
| `minAwareness` | 0.1 | 技术下限 |

**为什么它最优**：
1. **现成**：SUMO 自带，不用写新模型。
2. **物理合理**：现实驾驶员本来就会看错车距、反应慢。这不是作弊，是补上缺失的机制。
3. **不换模型**：支持 Krauss，我们的场景不用改跟驰模型，只加设备。
4. **可标定**：调 `initialAwareness` 就能连续改变事件率，可以做剂量—响应。
5. **有出处分**：TransAID 项目报告 §2.3.1.3 专门讲了这个模型。

**风险**：参数要标定到「事件率 ≈ 17–23 件/车小时」，需要一轮扫描。

### 路径 2：注意力中断（blackout）模型

**是什么**：车辆进入指定区域后，按概率进入 3 秒「不响应环境」状态，实现方式是 TraCI 把该车的 `actionStepLength` 改成 3.0 秒，到期改回。

**出处**：Leich, Nippold & Wagner, *Reproducing Weekly Crash Patterns Using a Minimalist Driver Error Model*, SUMO User Conference 2026 (pre-print 3232)，DLR 与柏林工业大学。

**他们的参数**：小汽车激活概率 4.7%、卡车 1.6%、自行车 0.5%；进入区域后有 12–35 秒的随机延迟；3 秒中断；100 次独立重复。结果：模拟的周内碰撞模式与现实吻合。

**为什么值得做**：
1. **有同行评审的论文背书**，方法站得住。
2. 3 秒「看不见」和现实里「低头看手机」同构，审稿人好接受。
3. 实现就是一个 TraCI 脚本，改动小。

**风险**：论文没有公开代码，要自己写；概率需要针对我们场景重新标定。

### 路径 3：EIDM 跟驰模型

SUMO 官方扩展模型，原生带驾驶误差参数。**限制**：官方明确要求步长 0.05–0.5 秒（我们正好 0.05，兼容），且不兼容 actionSteps 特性。
**风险**：换模型等于换整套动力学，前面所有校准作废；而且审稿人会问「为什么选这个模型」，不如路径 1 只加设备来得干净。**列为备选**。

### 路径 4：参数调整（tau / apparentDecel / sigma）

最简单但最弱。`tau < 步长` 产生的碰撞是数值伪影，不是行为；`apparentDecel` 有物理含义但说服力有限。**只作为诊断用，不作主路线**。

### 路径 5：网络结构（瓶颈、合流、匝道）

我们其实已经跑过：车道缩减能把事件率带到 18.2–25.5，正好落进现实区间，但密度被推到 51–55（现实 43.5），状态越界。记录里写「判伪规则已触发，未尝试第三种编码」。
**判断**：不是死路，但已有证据说「形状对了、水平不对」。若要用，必须先解决「密度过高」，否则跟路径 1 冲突。

### 路径 6：真实需求序列（用 NGSIM 上游穿越序列作边界）

用真实车辆到达序列代替泊松排班，产生真实的需求起伏 → 波 → 冲突。工作量大，但最接近现实。**列为长期方案**。

## 四、推荐

**先走路径 1（driverstate），路径 2 作为并行备选。**

理由：
1. 它补的是**缺失的机制**（驾驶员会犯错），不是调参数凑数。
2. 它保持 Krauss 模型不变，前面所有校准不用推翻。
3. 它直接回应了评审提出的「构念效度」质疑——如果模型里有驾驶员失误，它就能产生现实量级的风险事件，这条质疑基本消解。
4. 成本最低：改配置 + 一轮参数扫描，不写新模型。

**如果路径 1 扫描后事件率仍然上不去**，再上路径 2（blackout），因为它可以强行制造中断，不依赖参数微调。

---

## 五、下一步要验证的三件事

1. **driverstate 能否在现有场景里产生 Formal P2 量级的事件**：给全部车加设备，`initialAwareness` 从 0.9 扫到 0.3，看事件率曲线能否进入 17–23。
2. **加了失误模型之后，交通状态会不会跑偏**：密度、速度、时距必须仍在现实区间内，否则又变成「状态对了机制不对」的老问题。
3. **路径 1 与路径 5 会不会冲突**：如果 driverstate 已经把密度推高，就不能再叠瓶颈。

---

## 六、这次没证明什么

- 没有跑任何实验，全部是文档与规格核对。
- 两条路径的**事件率能不能标定到现实水平**，未知，必须实跑才知道。
- driverstate 在 SUMO 1.26（我们版本）上的具体行为没有实测。
- 路径 1 和路径 2 的组合效果没有依据。
