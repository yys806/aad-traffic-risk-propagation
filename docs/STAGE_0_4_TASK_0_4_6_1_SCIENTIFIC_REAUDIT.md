## 1. PDR/PER 分母复核（任务 §1）

### 1.1 三种口径的独立复算（逐运行，机器可读见 `code/outputs/formal/calibration/stage_0_4_see_v2x_reaudit_v1/reaudit_results.json`）

**口径定义**：
- **完整运行 PDR（full-run）** = 本运行全部接收数 / 本运行全部发送数（分母=tx 行数，含运行边界未被接收的部分）。
- **共同窗口 PDR（common-window）** = 接收覆盖的序号区间 [rx_min, rx_max] 内的接收数 / 该区间内的发送数（剔除运行首尾未被接收的边界段）。
- **字段 `per_ue_loss_pct`**：README 报告值（换算 PDR ≈ 1 − loss%/100）。

### 1.2 Run 2 重点解释（原报告 PDR=100% 的来源）

- **Fact**：Run 2 发送 5,742、接收 5,591；接收端覆盖序号区间 [151, 5741]（共 5,591 个），**窗口内零间隙**（`rx_seq_gaps_gt1=0`）；区间外 [0,150] 的 151 个发送序号**全部未在接收端出现**。
- **完整运行 PDR = 5,591/5,742 = 0.9737**（真实端到端投递率）。
- **共同窗口 PDR = 5,591/5,591 = 1.000**——即 0.4.6 报告的 100%。
- **0.4.6 的错误**：0.4.6 的 `audit.json` 写 `independent_pdr=1.0`，与 0.4.6 报告正文 `发送 5,742 / 接收 5,591` 自相矛盾——0.4.6 脚本把分母取成了"接收覆盖窗口内的期望数"而非"全运行发送数"，把**边界未接收段排除在分母外**，从而把 97.4% 报成 100%。**这不是"两个口径都对"，而是 0.4.6 口径选错并误导了结论**。
- **Run 7 同理**：发送 4,899/接收 4,899，全序号 0..4,898 完整覆盖，完整运行 PDR=1.0（真 100%，无边界损失）——Run 7 的 100% 是真实全投递，Run 2 的 100% 是窗口假象。

### 1.3 原报告 PDR 是否正确？差异来自哪里？

- **0.4.6 报告说"sender-base 复算与字段逐 run 一致、分母=发送数"——不成立**：其复算分母实为接收覆盖窗口（把边界发送排除在分母外），与"分母=发送数"的表述矛盾。逐 run 的**完整运行 PDR** 才是"分母=发送数"的正确实现，且与字段 loss% 存在 −0.3 至 −5.0 pp 的系统差。
- **字段 `per_ue_loss_pct` 的实际口径（Inference，高置信）**：其分母≈**接收端覆盖的序号窗口内的期望发送数**（即共同窗口口径），非全运行发送数。故 run 2 字段=0% 也是同一窗口假象的反映。
- **哪一种 PDR 口径有可靠物理意义（任务验收 2）**：**完整运行 PDR（full-run）**——分母明确（运行内全部发送）、接收机会明确（发送即机会，发送端 seq 0..N−1 连续无重复、无重启、日志完整）。共同窗口/字段口径可用于"窗口内投递质量"但**系统性高估**（剔除边界损失），**不应用于 AAD 校准分母**。
- **日志完整性**：10/10 运行 `tx_duplicate_seq=0`、发送 seq 0..N−1 连续、接收端 `rx∩tx` 无发送日志缺失的孤立行——"序号间隙=丢包"在运行内成立。

### 2.3 跨设备时钟偏移与漂移诊断

- **跨运行中位数偏移（Fact）**：P50 跨运行从 8.8 ms（run2）到 32.0 ms（run8），极差 ~23 ms。若各运行共享同一对设备且真实时延相近，则**各运行存在不同的跨设备固定时钟偏移**（O_t3 − O_t1），直接叠加进 `latency`。这与 0.4.6"绝对值可能含固定偏移"一致，且量级更大。
- **运行内漂移（Fact）**：前/后半中位数差 run0 +0.018、run4 +0.093（可忽略），run2 −6.838、run3 +2.640、run5 +4.014、run9 +3.029（显著）。漂移与真实时延变化、真实丢包导致的中位数估计不稳**不可区分**（样本内无共钟参考点）。
- **时钟证据（Unverified）**：官方 README/论文/脚本仍无共用钟、GNSS-PPS/PTP 或实测互偏移说明。现有数据**无法解决**时钟同步问题（任务验收 4）——缺少：①发送/接收主机时间戳的同步架构声明；②互偏移实测或共触发事件；③`tx_timestamp` 的捕获点（发送端打戳 vs 接收端重构）。
- **分层可信度结论（任务验收 3）**：
  - **运行内分布形态/抖动/jitter（运行内相对变化）**：相对可信（同运行共享同一对时钟，形态反映真实时延变化）——但 run2 等存在显著漂移，形态含漂移成分。
  - **运行内绝对时延水平（P50 等绝对值）**：**不可信**（含未知固定偏移）。
  - **跨运行合并分布/合并分位数（0.4.6 报的 P50=16.787 等）**：**不可靠**——它混合了真实时延差异与各运行不同的固定偏移（8.8–32 ms），是"真实 + 偏移"的混合体，不得作为 AAD 校准输入。0.4.6 的合并分位数据此**降级**。
- **不得宣称**"同行时间戳=共用时钟"或"分布形态必然可靠"（任务红线）——本复核确认二者均不成立。
