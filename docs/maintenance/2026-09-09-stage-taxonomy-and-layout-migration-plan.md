# 阶段编号与项目布局迁移计划

## 目标

- 当前研究与工程入口统一使用“阶段 X.X”；机器标识使用 `stage_X_Y`。
- 保留历史证据的原始含义，并登记旧编号到新阶段的迁移关系。
- `paper/` 与 `literature/` 保持根目录用户入口。
- 根目录原始数据统一迁移到 `dataset/`，代码和清单同步改用新路径。
- 根目录 `记录/` 迁入 `docs/归档/项目记录/`，由 `docs/HISTORY_INDEX.md` 提供统一入口。
- 实验、结果和进展继续由 `PROJECT_CONTEXT.md`、`docs/PROJECT_REGISTRY.json`、
  `docs/RESEARCH_STATUS.md`、`docs/STAGE_INDEX.md` 与阶段执行记录共同维护。

## 执行顺序

1. 跑迁移前基线验证并保存准确状态。
2. 迁移 `记录/` 与原始数据目录，更新忽略规则和所有路径引用。
3. 重命名当前阶段 0 的代码、脚本、测试和技术账本；更新导入与命令。
4. 将当前计划、注册表、索引、状态和协议 Gate 改为新阶段编号。
5. 保留历史文档原始编号，在历史索引中登记映射；不改写历史结论。
6. 更新便携证据导出路径，运行文档校验、证据校验、测试和编译。
7. 检查旧根目录已消失、`dataset/` 完整、Git 状态只含预期迁移。

- 全量测试、`compileall`、严格文档校验与便携证据校验通过。
