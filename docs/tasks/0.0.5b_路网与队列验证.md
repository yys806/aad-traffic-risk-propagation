## 一、第 1 步：路网与三档绕行代价（✅ 通）

用 netconvert 建网，实测各边长度：

| 边 | 长度 | 作用 |
|---|---|---|
| in | 2998.5 m | 0 → 改道点 |
| mid | 1898.5 m | 改道点 → 瓶颈上游 |
| bn | 200.0 m | **瓶颈段**（4900–5100 m） |
| out | 1898.5 m | 瓶颈下游 → 汇合点 |
| tail | 998.5 m | 汇合点 → 终点 |
| **bypass** | **5500.0 m** | 绕行路（3000 → 7000） |

自由流：
- 主路改道点→汇合点 = 1898.5 + 200 + 1898.5 = **3997 m → 133.2 秒**
- 绕行路 = 5500 m → **183.3 秒**
- **差 50.1 秒** ✅ 正是预注册的 **+50 秒档**

三档对应绕行路长：+30 秒 → 4900 m；+50 秒 → 5500 m；+60 秒 → 5800 m。

## 二、第 2 步：瓶颈队列能否形成、回溢、消散（✅ 通）

配置：+50 秒档，需求 1600 辆/时，瓶颈在 t=600–780 s 把限速压到 4 m/s。

| 指标 | 实测 |
|---|---|
| 总车辆 | 747 |
| 到达 | 592 |
| **主路低速车（<5 m/s）峰值** | **35 辆** |
| **队尾最上游位置** | **4024 m** |
| 改道点位置 | 3000 m |
| **队尾是否回溢到改道点** | **否**（最近距离 1024 m） |
| 低速车 ≥20 辆的时段 | 748 – 868 s |
| 绕行路使用车辆数 | 0（本步只发主路路由，正常） |

### 三条都成立

1. **队列能形成**：峰值 35 辆车在 5 m/s 以下
2. **会向上游回溢**：队尾从瓶颈（4900 m）回溢到 **4024 m**，退了 876 m
3. **会按时消散**：瓶颈解除后约 90 秒内低速车归零

### 对预注册的意义

**队尾停在 4024 m，没有回溢到 3000 m 的改道点。**

这正是我们要的工况：**车到改道点时，本地看不出下游堵了**——
按 GPT 的规则，这个工况可以如实算作「本地无线索」，
而不是靠开关把线索抹掉。

反过来，如果哪天队尾回溢过 3000 m，那个种子要**单独报告为「本地已有线索」**，不许删。

## 三、这一轮没证明什么

1. **绕行路一辆车都没走**（本步只发主路路由），所以「绕行要多久」只有理论值，没有实测
2. **没有消息臂、没有决策规则**，第 3–5 步全没做
3. **瓶颈用「限速压到 4 m/s」模拟容量下降**，是一种近似；
   真实的容量下降（如事故占道）在 SUMO 里还有别的实现方式，本轮没比较
4. **单车道**，没有换道行为
5. 需求 1600 辆/时是拍的，没按实测标定
6. 只跑了一个种子、一个瓶颈时长
