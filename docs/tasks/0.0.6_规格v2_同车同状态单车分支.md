## 一、v1 错在哪（GPT 指出的，我认）

**我要的是「同一辆车、同一个决策状态、两条路各走一次」。
成对探针给的是「两辆车、两个状态、各走一条路」。**

- 前车过线时刻 t，后车晚 δ 过线。配对误差 = `T_绕(t) − T_绕(t+δ)`。
  汇合口等待在增长时低估 Y，在下降时高估 Y。**方向不固定，没有上界。**
- 而且有直接的规格冲突：1600 辆/时下均匀车距是 **2.25 s**，
  「相邻车」「晚 1 s」「均匀发车不改需求」三者不能同时成立。

## 二、正确做法（GPT 给的，我采纳）

> **对基线中到达决策点的车辆 i，从决策状态 S_i 出发，一支走主路、一支走绕行。
> 两支保持未来外生输入与其他车辆的控制规则相同，但允许其他车自然响应这一次改道。**

**一行 Y 的定义：一个基线车辆、一个可执行的决策状态、两次只改变该车路线的运行。**

## 三、模块拆解与验收（不过不进下一个）

### 模块 0：决策点与路线可行性

- 在路网中标定物理 3000 m、对应车道坐标、最后共同可控状态、共同终点
- 规定在哪个仿真步边界下发路线：**先读 B → 再改路 → 再推进**
- **验收**：
  - 单车分别通过两支，核对实际经过的道路与终点
  - 有并行车的用例验证两条路线从**同一车道状态**合法可达：不瞬移、不强制换道
  - 验证「预先规定的步边界」与「物理 3000 m」之间的误差
  - **若 3000 m 处已不能合法选两路，就停下来**，不许悄悄把更上游的状态算成 3000 m

### 模块 1：基线与样本名单

- 跑一条**不因测量改路**的基线
- 对候选车记录：ID、实际发车时刻、决策步 t_i、车道、位置、速度、当时的 B_i
- **验收**：
  - 全量对账：计划 / 实际插入 / 过线 / 到达 / 未完成
  - 按时段核对实际入口流量与 `departDelay` 分布
  - 若由 `<flow>` 换成显式清单，**不能只用车辆总数证明背景等价**
  - 子样本抽样规则要**预先固定按车辆抽**，不按配对成败或结果删样本

### 模块 2：同状态重放

- 优先：动作前 `traci.simulation.saveState`，分别 `loadState`
- 固定 SUMO 版本、步长、配置、随机状态、外生事件；外部控制器状态也要保存或重建
- 若快照不能忠实恢复 → 改为从仿真起点**确定性重放**到 t_i
- **验收（不改路对拍）**：
  - 从检查点继续，必须**复现连续基线**
  - 不只比最终均速：逐步核对车辆 ID、车道、位置、速度、出发与到达事件
  - 至少覆盖三种情形：自由流、排队中、瓶颈启停附近
  - 数值容差预先写死
  - **两种方法都复现不了 → 不能声称两支从同一状态出发**

### 模块 3：单车分支执行

- 每辆样本车从同一 S_i 独立开两支，只改变目标车剩余路线
- 未来需求、事件、控制逻辑相同；**不强行锁定其他车辆轨迹**
- 每辆车两支跑完即丢弃，不影响后续样本基线
- **验收**：
  - 分支前核对同一 t_i、B_i、状态
  - 分支后核对实际走过的路线、没有被自动重路由覆盖、到达同一终点
  - 与基线路线相同的那一支，**必须复现该车的基线到达时间**
  - **交换两支执行顺序，结果须一致**
  - 路线不可达 / 未到达 / 被移除 / 影响测量的瞬移 → 单列原因，不许记成正常行程
  - 预先规定最长运行时长与未完成处理

### 模块 4：时间与 Y

- 直接记录两支到达时刻 `a_主`、`a_绕`
- `T_r = a_r − t_i`；`Y = a_主 − a_绕 + 55.7` 独立复核
- **验收**：
  - 用已知时间戳的测试记录，同时检验**时间起点、路线标签、公式**
  - **单车空路分别验两个 T 和 Y**——不能只验 Y，因为共同时间偏差会在 Y 里抵消掉
  - 用跨步过线的轨迹检验 3000 m 的坐标与计时约定
  - 到达时刻与连续运行的 `tripinfo.arrival` 对拍

### 模块 5：冻结查表

- 用分支**之前**同一个 B_i 分箱；**一辆车只贡献一个 Y_i**
- **验收**：手算小表逐项对拍箱边界、计数、均值、稀疏箱回退
- 报告每箱候选数、成功数、缺失原因、时间覆盖
- **`n ≥ 5` 只是最低覆盖门槛，不表示这 5 辆车是独立重复**；单种子表只证明流程跑通

## 四、动手顺序（GPT 指定）

**先模块 0 的单车与车道可行性测试 → 再模块 2 的无动作恢复测试 → 最后才批量生成分支。**

理由：这两个是最值得先验的假设——
**同一状态下是否真能选两条路**，以及 **SUMO 是否真能把该状态重放出来**。
任何一个不过，都不许先生成一批看起来合理的 Y。

## 五、GPT 指出的、我原来会「错了也过」的四条验收（已修正）

| 我原来的 | 问题 | 改成 |
|---|---|---|
| `Inserted = 生成数` | 所有车即使普遍晚 100 s，只要最终插进去照样通过 | 按时段对比计划/实际插入，写死允许的延迟与积压门槛 |
| 两个 T 各自误差 <3% 且 `Y≈0` | 两路都错过线时刻 4 s，两个 T 都能过 3%、Y 完全不变 | **独立验绝对过线时刻与终点**；`Y≈0` 写明秒级容差 |
| 「堵塞时 Y>0」 | **错**。Y>0 只表示主路额外延误更大；主路实际更慢是 **Y>55.7** | 改正表述 |
| 队长变化 <5%、队尾差 <100 m | 队尾相同也可能放行率/车道状态/汇合等待不同 | 只作**诊断报警**，不作同状态证明 |

**另外**：我原来写的「堵塞期 Y 落在 60–150 s」是错的区间运算，
按表中两个预测区间算应是 **95.7–150.7 s**。
