样本车 V0251，决策时刻 686.4 s（堵塞开始后 86.4 秒），位置 2994.2 m，速度 22.97 m/s。
堵塞期内决策的车共 88 辆。

**机制层面：模块 3 通过。**

## 二、但数值明显不对

`T_主 = 995.7 − 686.4 = 309.3 s`，`T_绕 = 1270.0 − 686.4 = 583.6 s`，**Y = −218.6 s**。

绕行路剩余只有 `(2998.5−2994.2) + 5500 + 998.5 = 6503 m`，自由流 217 秒。
**实测 583.6 秒，多出 367 秒。**

## 三、轨迹把根因说得很清楚

绕行支抽样轨迹：

| t | 所在边 | 位置 | 速度 |
|---|---|---|---|
| 714.8 | bypass | 828.3 | 29.39 |
| 814.8 | bypass | 3767.4 | 29.39 |
| 864.8 | bypass | 5236.9 | 29.39 |
| **914.8** | **bypass** | **5499.9（路尽头）** | **0.00** |
| 964.8 – 1214.8 | bypass | **5499.9** | **0.00** |
| 1264.8 | tail | 847.6 | 28.54 |

**车以 29.4 m/s 跑完 5500 m 的绕行路，在尽头原地停了约 300 秒，才进入 `tail`。**

## 四、根因

汇合口 n7 是 **priority 交叉口**：`tail` 单车道，同时接收 `out`（主路）与 `bypass`（绕行）。
主路车流 1600 辆/时、间距约 67 米，而 30 m/s 并入需要约 100 米净空。

**=> 绕行车永远等不到足够空档，只能等主路流量下降才挤进去。**

**这是结构性缺陷，不是参数问题。** 若带着它跑，**每一个 Y 都会被虚高约 300 秒**，
而单看数字完全看不出来——只会得出「绕行毫无价值」的错误结论。

## 五、修法（标准交通工程做法：加汇合车道）

现状：`out` 与 `bypass` 都并入单车道 `tail`，必然抢道。

改为：**`tail` 设两车道**，`out` 接 0 车道、`bypass` 接 1 车道，两股车流各走各的，到终点自然结束。
这等价于真实高速的「汇合后双车道」段，不需要强制并线。
