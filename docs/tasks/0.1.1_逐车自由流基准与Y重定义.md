## 一、为什么要重做

88 辆全跑后，`T_绕 > 230 s` 的车有 22 辆，额外 22–58 s，而汇合等待只有 4 s。
追了最慢的 V0262，轨迹显示**全程匀速 23.41 m/s，一秒都没堵过**。

根因：vType 只写了 `speedFactor="1"`、**漏写 `speedDev="0"`**，
SUMO 默认 `speedDev=0.1`，每辆车从 N(1, 0.1) 抽自己的期望车速。
反推实测 **0.79–1.02 倍（23.8–30.5 m/s）**。

**结论：那 22 辆是开得慢的司机，路网本身干净。**

但它让 `Y = ΔT + 50.1` 里的 50.1 失效——那是假定 30 m/s 的代价。

## 二、GPT 第五十八轮的三点纠正

1. **选 B**：保留速度异质性，Y 改成逐车超额耗时差，空路基准**另跑实测**，不许用绕行耗时反推（否则循环论证）。
2. **我把偏差方向说反了**：展开式 `Y = ΔT + (T0绕 − T0主)` 里基准差是**加项**，慢车的基准差更大 → 正确 Y **更大**，旧式是**低估**。
3. **6507 与 6597 混用**：6597（从决策位置 2900 起算）才对；本脚本改为**直接从网络读边长度**，不再手打常数。

## 三、新定义

```
Y_i = (T主,i − T0主,i) − (T绕,i − T0绕,i)
```

`T0` = 同一辆车、同一条路线、同一计时起点的**空路自由流时间**，
并把该车实际抽到的 `speedFactor` 钉死（`speedDev="0"`）。

### 对拍预测（R08）

- **基准差在 30 m/s 车上应恰为 50.0 s → 实测下界 50.00** ✅
- 慢车基准差更大 → 实测上界 **64.10 s** ✅
- **新 Y ≥ 旧 Y** → 旧式下界 70.1、新式下界 **84.1**，差 14.0 s ✅（正对应最慢那辆车）
- 代数自检：`Y − ΔT = 122.0 − 71.4 = 50.6 ≈ 基准差中位 50.2` ✅

**旧式的真正问题不是「高估」，是漏算了慢车的绕远代价，把 22 辆车压低了 13–14 秒。**

## 六、必须写进论文的三条边界

1. **绕行超额耗时 ≈ 0 是因为每次重放只有一辆车改路**，绕行路上始终只有它一辆。
   这是**个体改路价值**，不是系统最优。
   若大量车辆同时改路，绕行会被加载、主路会更快清空，边际收益必然下降。
2. **速度异质性来自 SUMO 默认 `speedDev=0.1` 的抽样，不是实测驾驶员分布。**
   只能写成「本仿真设定下的驾驶员速度异质性」，不得当作已验证的真实分布。
3. 按 GPT：主分析保留异质性；`speedDev="0"` 作为**敏感性分析**，不替代主结果。
