## 十二、主口径冻结（GPT 第七十八轮裁定，看过后修订）

1. **DRAC 不封顶、不替换净距、不按 DRAC≥100 一刀切删帧。**
2. 主统计按**输入是否有效**筛选，不按 DRAC 结果筛选：
   `g ≤ 0` 与 `g` 缺失分别计数且不计算 DRAC；正净距帧用同一套前后车匹配、
   轨迹连续性、净距可信度规则检查全样本，**仅剔除有明确输入失效证据的帧**。
3. 另报一次「排除那 69 帧后按相同规则重建事件」的敏感性。
4. **强刹主窗口 = 1.0 s**（操作性定义，**不声称是已验证的最佳因果窗口**）；
   0.5 s 与 2.0 s 同时作为敏感性报告。
5. 冻结时须写明：窗口相对哪个事件时点、追踪哪一辆前车、观测不足怎么处理。
   **换道/切入事件中不得把不同车辆的加速度拼成「连续三帧」；观测不足与「未检出」分开。**
6. 后车换道**不自动排除**：若换道后可信配对中观察到正净距与相对接近且满足统一判据 → 计入并标记；

7. 比例更正：「后车换道 + 他车切入」= 140/433 = **32.3%**；
   「前车关系改变」（再加前车驶离）= 183/433 = **42.3%**。

## 十五、🔴 撤回：两处缺陷（2026-11-20 23:15，Gemini 第七十九轮指出，研Dive 已复算核实）

### 15.1 缺陷一：把「自车加速度」当成了「前车加速度」

**代码证据（已读源码核实）**：`code/src/riskprop/real_trajectory.py` 第 75–84 行的 `lookup` 表里
**只有前车的速度 `_leader_speed_fps` 与车长 `_leader_length_ft`，没有前车的加速度**；
而第 180 行 `result["acceleration_mps2"] = _numeric_optional(result, ("v_Acc","v_acc"))`
写入的是**本行（后车/自车）自己的 `v_Acc`**。

我却在 `ngsim_drac_events.py:165` 与 `ngsim_qc.py:99` 把它当作前车加速度用。

**实测对拍（DRAC≥100 的帧）**：

| 帧 | 自车 v_Acc | 前车 v_Acc | 代码实际取到 |
|---|---|---|---|
| 407@1325 | 0.475 | **−2.213** | 0.475 ❌ |
| 590@1743 | −1.195 | **−3.414** | −1.195 ❌ |
| 1054@2773 | 0.238 | **−0.652** | 0.238 ❌ |

**受影响**：QC3 三窗口（1.8% / 9.2% / 22.4%）、QC4 强刹检出（77.6% / 22.4%）、
QC4 交叉表整张、原始标签里的「前车强刹 0.5%」。
**不受影响**：净距、闭合速度、DRAC、事件合并、事件总数（433）、净距分层、三个净距/速度敏感性。

### 15.2 缺陷二：42.3% 的事件涉及摩托车钻缝

US-101 位于加州，**摩托车合法车道穿行（lane splitting）**。

| 项 | 数值 |
|---|---|
| 事件中**后车是摩托车**（`v_Class=1`） | **183 / 433 = 42.3%** |
| 事件中前车是摩托车 | 7（1.6%） |
| 摩托车占全部车辆 | **45 / 6,101 = 0.74%** |
| DRAC≥100 的 69 帧中后车是摩托车 | **37**（53.6%） |

**摩托车只占 0.74% 的车辆，却贡献 42.3% 的事件。**
这类事件在 `Space_Headway` 上表现为厘米级净距，物理上是**侧向并行穿行**，不是 1D 纵向跟驰冲突。

**这解释了为什么净距 <1 m 的层率高达每千车·公里 1.5 万–3.2 万。**
