## 三、更麻烦的问题：τ 标定可能是循环论证

### 3.1 一个对不上的数字

- 区域场景实测稳态净距 **36.36 m**、速度 **21.378 m/s**
- 反推 τ = (36.36 − 2.5) / 21.378 = **1.584 s**
- 0.0.2 高速层中位 = **1.559 s**（几乎相同）
- 54–80 层中位 = **1.412 s**（明显更小）

**我们的车以 77 km/h 开，却留着「开 100 km/h 的司机」才留的车距。**

### 3.2 为什么会这样——两个可能，我分不清

| 可能 | 说明 |
|---|---|
| **(a) 循环论证** | `fork_scenario.py` 里 vType 的 τ 硬编码 1.584 → 车流稳态车距 = v·τ + minGap = 36.36 → 再拿这个车距反推 τ 当然得 1.584 |
| **(b) 真实如此** | 77 km/h 的司机确实可能留 1.584 s 车距，而 54–80 层中位 1.412 是全体平均，含更多激进司机 |

**现有数据无法区分。**

### 3.3 如果是 (a)，后果很严重

**「区域场景的 τ 是从实测标定来的」这个说法就是错的。**
正确的表述只能是：**「我们设定了 τ=1.584，车距是它的产物，不是独立验证。」**

这会影响论文 Calibration 一节的可信度。

## 四、如果改成按 54–80 层抽样，代价很大

按 τ 中位 1.412 重设，区域场景稳态车距会从 **36.36 m** 缩到
`1.412 × 21.378 + 2.5` = **32.7 m**（缩小 3.7 m，约 10%）。

**这会改变整个路网的排队与容量特性**：

| 已验收项目 | 是否需要重跑 |
|---|---|
| 0.0.7 模块 1 流量验收（746/695/592） | **需要** |
| 0.0.5b 队列验证 | **需要** |
| 0.0.8b 汇合口修法（自由流 166.7–170.1 s） | **需要** |
| 0.1.7 分岔风险审计（峰值 1.805/1.779） | **需要** |
| 0.2.4/0.2.7 区域停车组 | **需要** |

**换句话说：改 τ 等于把 P2 之后的所有数字推翻重来。**

## 五、一个折中方案（未验证）

**只对「响应车」做 τ 异质，源车与前方车流保持 τ=1.584。**

理由：AAD 关心的是「后车如何响应扰动」，而扰动源本身的车距特性不是研究对象。

**但这会造成模型内部不一致**：同一车流里既有 1.584 又有分布抽样，
审稿人可能质疑「为什么扰动源和响应车用不同参数」。

3. **没评估改 τ 的成本**：只列了受影响项目，没测算重跑工作量
