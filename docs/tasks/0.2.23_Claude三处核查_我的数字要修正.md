## 一、Claude 的三处核查，逐条验

### 1.1 问题一：区域场景的「有刹车」是永久阻断，不是 2 秒脉冲 —— **成立**

`region_pair.py` 的逻辑：源车以 9 m/s² 减速，直到速度 ≤ 1e-6 时置 `stopped=True`，
**之后再也不释放**，且 `setSpeedMode(0)` 已关掉原生安全约束。

**所以区域场景里源车是「停在车道上不动」，不是「踩一脚急刹就恢复」。**

**后果：0.2.22 的 10 种子结果应改名为「车道阻断后的队尾追近」，不能叫「急刹」。**

我此前把 0.2.19（单车台架 2 秒脉冲）与 0.2.22（区域永久阻断）混着说，是错的。

### 1.2 问题二：队尾在窗末碰到测量区边界 —— **成立**

测量覆盖 `mid / bn / out / tail`，**不含 `in` 边**。
Claude 探针显示队尾 t0+590 s 已退到 7.4 m（`mid` 起点），即将越界。

**后果：若窗口延长或需求变化，风险可能落到不测的区域，导致「看起来降了」其实是「挪出去了」。**

### 1.3 问题三：0.1 s 与 0.8 s 的比较还换了积分方法 —— **成立，且已修**

SUMO 日志原文：
```
Warning: Action step length '0.80' is used for vehicle type 't1.584'
but step-method.ballistic was not set. Setting it now to avoid collisions.
```

**0.4 / 0.8 / 1.2 / 1.6 s 的臂被自动切成 ballistic 积分，0.1 s 臂仍是默认 Euler。**

**0.2.19 的扫描混了两个变量：延迟 + 积分方法。**

### 2.1 只有 0.1 s 那一臂变了

因为只有它原来用 Euler 积分，其余四臂本来就是 ballistic。

### 2.2 延迟效应比我说的弱

| | 修正前 | 修正后 |
|---|---|---|
| 0.1 s → 0.8 s 的增幅 | 1.628 → 3.455（**2.1 倍**） | 2.885 → 3.455（**1.2 倍**） |

**但「零延迟只有 1.6」这个数字被高估了，真实是 2.88。**

**换句话说：0.1 s 时已经接近 3.4（2.885），延迟的边际作用比我原先说的小。**

## 四、现在站得住的与站不住的

### 4.1 站得住

- 原生 Krauss 零反应延迟（0.1 s）+ Euler 积分 → DRAC 上不去（1.63）
- 加反应延迟后 DRAC 上升，0.8 s 越阈（3.455）
- 区域场景里，无扰动 10/10 零事件，有扰动 10/10 有事件（6–16 个）
- 峰值 DRAC 不可用（净距趋零发散到 264）
- 「碰撞」不是真撞（4,765 帧报警 vs 0 帧真实接触）

### 4.2 站不住 / 需修正

- 「延迟效应 2.1 倍」→ 实际 1.2 倍
- 「区域是 2 秒急刹」→ 是永久车道阻断
- 「km_plan 分母合理」→ 无物理意义，需重定义
- 「测量覆盖完整」→ 不含上游 `in` 边，队尾会跑出去
