## 一、参数层：SUMO 默认值实测读回（SUMO 1.26.0）

**测试方法**：建一个只写 accel/decel/sigma/tau/length/minGap/maxSpeed/speedFactor 的 Krauss vType，
用 TraCI 的 `getEmergencyDecel` / `getSpeedDeviation` / `getActionStepLength` 等读回真实生效值。

| 参数 | 不写时的实际值 | 我们是否知道 | 影响 |
|---|---|---|---|
| **speedDev** | **0.1** | ❌ 未在任何区域脚本或 R5 声明 | 每车抽期望车速 0.65–1.29×，单车道形成移动路障 |
| **emergencyDecel** | **9.0** | ✅ 与 EDI 上限 5.6 的推导一致 | **好消息：5.6 有依据**（=9.0−3.4） |
| **apparentDecel** | **4.5（= decel）** | ✅ 与假设一致 | 前车减速超 4.5 才破界 |
| **actionStepLength** | **1.0 s** | 🔴 未声明，多数脚本按默认跑 | **决策间隔是 1.0 秒，不是 0.1 秒** |
| imperfection（sigma） | 0.5 | ✅ 我们显式写 0 | — |

**所以 0.2.16 / 0.2.17 / 0.2.20 / 0.2.22 全部在「speedDev=0.1 生效」下跑，而这个条件从未被声明。**

### 1.3 一个新发现：τ 必须 ≥ actionStepLength

SUMO 实测警告（τ=1.35、actionStepLength=1.6）：

> `Warning: Given action step length 1.6 for vehicle type 't' is larger than its parameter tau (=1.35)! This may lead to collisions.`

**这独立证实了 Claude 在 0.2.26 提的「τ ≥ 动作步」要求，且说明 R5 v0.3 里保留的 1.6 s 块在 τ=1.35 下非法。**

### 1.4 一个好消息：ballistic 会被自动打开

实测警告：

> `Warning: Action step length '0.80' is used for vehicle type 't' but step-method.ballistic was not set. Setting it now to avoid collisions.`

**只要 actionStepLength > step-length，SUMO 自动开 ballistic。**
所以过去那些设了 actionStepLength 的跑法，积分器事实上已经是 ballistic——
R5 要求「强制 ballistic」不改变已有结果，只是把它写明。

### 1.5 一个曾经的误报（我自己吓自己）

我最初的测试配置没写 `<processing><step-length value="0.1"/></processing>`，
于是 step-length 默认 1.0 s，`actionStepLength="0.8"` 不被 1.0 整除 → SUMO 把它调成 1.0。

**补上 step-length=0.1 后，0.8 完好保留，无警告。**

→ **我们的脚本都设了 step-length=0.1，所以 0.8 秒没有被改。这条不是问题。**
