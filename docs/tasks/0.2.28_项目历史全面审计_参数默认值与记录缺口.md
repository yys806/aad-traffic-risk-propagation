## 7.1 `actionStepLength` 默认不是 1.0 s —— 我的重大误报

**错误说法**（§1、§1.2）：不写 `actionStepLength` 时实际 = 1.0 s，
所以 `region_admit` / `region_hetero` / `region_stop` 按 1 秒决策跑，57/82 处受影响。

**实测复核（step-length 分别取 0.1 与 1.0）：**

| step-length | 是否写 actionStepLength | 实际生效值 |
|---|---|---|
| **0.1** | **不写** | **0.100 s** |
| 0.1 | 写 0.8 | 0.800 s |
| 1.0 | 不写 | 1.000 s |
| 1.0 | 写 0.8 | 1.000 s（被调，因为 0.8 不是 1.0 的整数倍） |

**SUMO 的规则是：不写 `actionStepLength` 时，它等于仿真步长 `step-length`，不是固定 1.0 s。**
（`--save-template` 里 `<default.action-step-length value="0">` 就是这个意思）

**所以：我们的脚本都设了 step-length=0.1 → 不写 actionStepLength 时实际就是 0.1 s，即"每步决策"。**

**结论：§1 与 §1.2 的"按 1 秒决策跑"完全不成立。历史脚本没有这个问题。**

### 我为什么会错

step-length 用了默认 1.0 s，于是读到 1.0 s。
