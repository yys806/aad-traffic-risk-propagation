## 二、源车怎么选（GPT Q1，已改）

- **从 `t_src = 600 s` 起逐仿真步检查**（不是只在 600 s 那一刻查一次）
- 候选条件：在预定路线上、`mid` 上、沿路线距 `bn` 入口 **≤ 200 m**
- 选**最近者**；并列按车辆 ID 固定排序
- **等待上限 30 s**（跑前写死）；首次实际施刹时刻记为 **`t0`**
- **分析窗统一为 `[t0, t0+H]`**（不是 `[t_src, ...]`）
- **到期无合格车 → 记「未触发」，不补种子**
  - 在 8/10 准入分母中**仍占一席**
  - **不得报告成「施刹后零事件」**
- **不得根据初速、跟车间距、有无跟驰车改选**

## 三、制动波形（GPT 第八十二/八十三轮定，已冻结）

**指令速度以 9.0 m/s² 递减，最长持续 2.0 s，首次触零则提前结束。**

| 项 | 冻结值 |
|---|---|
| 指令下降斜率 | **9.0 m/s²** |
| **最长脉冲时长** | **2.0 s**（第一控制步到末控制步） |
| 结束条件 | **2.0 s 到** 或 **触零**，先到先结束 |
| 触零处理 | 末条指令为零则在对应控制步生效，**下一控制更新撤销覆盖**；<br>**不额外保持零速，也不在同一次更新里下发零速又立即撤销** |
| 解除后 | **恢复源车原安全模式，不再发任何速度指令** |
| 是否刹停 | **不必刹停**（30 m/s 时 2.0 s 末指令为 12 m/s） |

**关键澄清（GPT C2）**：
- `9.0 m/s²` 定义的是**指令下降斜率**；`2.0 s` 与**触零**是**结束条件**，先到哪个按哪个
- 解除后**不再指定速度**：源车是否停留、何时加速、能否回到限速，**由前方交通与原生模型决定**
- 后车不会把它「推着走」
- **实际减速度未必等于指令值，须分别记录**

**依据说明**：2.0 s 是**工程设计值，不是已验证的最优值，也不保证越阈**。
跑前须定死步长与 2.0 s 对应的控制步数。**先导不能用于回调脉冲。**

**不可复用 0.2.2 波形的理由**（已核脚本）：0.2.2 是「减到 0 后持续覆盖为 0」，
属于持续停车而非有限脉冲。**可复用的是减速段更新公式，不是完整波形。**

### 3.1 两种「未施刹」都要单列

| 情形 | 处理 |
|---|---|
| 30 s 等待期内**无合格候选车** | 记「**未触发**」 |
| 选中了但**源车已为零速、无法实际下发降速指令** | 记「**选中但未施刹**」 |

**两者都不换车、不补种子，仍占正式准入分母一席，不得报为「施刹后零事件」。**

## 四、`H` 的确定（GPT Q3 + Q6，已改）

### 4.1 消散判据（操作定义，非已验证标准）

> 在**跑前固定的观测期**与**监测车道**内，**最后一个慢车帧之后连续 60 s 为零，
> 且此后到观测结束未再出现慢车**，才确认该次消散。全程无慢车单列。

**三处必须写死（GPT 第八十三轮点名，v2 未写）：**

| 项 | 冻结值 |
|---|---|
| **监测车道** | `mid_0`、`bn_0`、`out_0`、`tail_0`、`tail_1`（覆盖上游溢出到 `mid`） |
| **观测期** | 从 `t0` 起 **600 s**（即最多观测到 `t0 + 600 s`） |
| **统一延长规则** | 若某先导到 `t0 + 600 s` 仍未确认消散 → **该次记「窗尾未消散」，`H` 暂停冻结**，须先与 GPT 商定延长规则再继续 |

- 慢车 = 速度 **< 5 m/s**
- **不能取第一次出现的 60 s 空档**（源车刚施刹时可能还没形成排队）
- **「全程无慢车」计入方式**：该次从 `t0` 到观测结束全程无慢车 → 记「**无排队**」，
  其 `H` 贡献按 **0 s** 计，并单列报告，不参与最大值比较

### 4.2 `H` 的取法

`H` = 各先导从 `t0` 到**消散确认**的最大耗时 **+ 60 s**。

- 五个先导都按同一规则触发、监测范围有效、**且均确认消散** → 可用它们冻结 `H`
- **有先导到期仍未确认消散 → 按 §4.1 的延长规则处理；无规则则暂停冻结**
- `最大值 + 60 s` **只是工程选择，不是总体上界**
- **正式运行不得逐种子延窗**

### 4.3 先导与正式种子

| 用途 | 种子 | 说明 |
|---|---|---|
| **先导（只定 H）** | 20261101–20261105（5 个） | **不进正式分析** |
| **正式（准入判定）** | 20261120–20261129（10 个） | 全新、未用过 |

**不必为了凑更多先导而移动正式种子**（GPT Q6）。

## 六、事件分类（GPT Q5，已改，按计算 DRAC 时的实际前车判）

**保持按后车去重，不因前车变更拆出更多事件。**
对每个去重事件，检查其**所有有效超阈帧**：

| 类别 | 定义 | 用途 |
|---|---|---|
| **直接事件** | 这些帧的前车**均为源车**；再标记后车是否为 `t0` 时的首辆跟驰车 | 直接效应 |
| **混合事件** | 部分超阈帧的前车是源车，部分不是 | **单列，不计入严格传播候选** |
| **非源前车事件** | 超阈帧的前车**均不是源车** | 见下 |
| ↳ **传播候选** | 非源前车事件里，**轨迹能追溯出施刹后按时间顺序形成的跟驰链**（如 源车 → A → B） | 区域传播 |
| ↳ 来源不明 | 追溯不出链条 | 单列 |

**严格传播候选的可复核规则（GPT 第八十三轮，跑前必须写死）：**

以**事件首次有效超阈帧**为追溯锚点，须同时满足：

1. **有逐帧前车记录**支持链条 `源车 → A → B`
2. 能按**预先规定的时序与减速判据**识别「A 在跟驰源车时的响应」
3. 且**该响应早于 B 的首次越阈**

**不计为严格候选的情形**：
- 仅有车辆先后出现
- 换道后接上
- 链条证据缺失

**即使链条成立，也只支持「与传播一致的候选」**，
**不凭 S0 断言急刹造成了多少额外事件**。

**两个关键规则**：
- **后来换上来的车直接跟着源车，也不算传播**（仍属直接事件）
- **不要求 A 自己先越阈**：A 跟着源车越阈是直接事件，B 跟着 A 越阈才是传播候选

**源车自身作为后车的事件不计入响应指标。**

### 6.1 暴露率（按运行计算）

> 分母 = 窗内、预定空间范围内**至少有一帧有效 DRAC 的不同有向车辆对**
> 每个去重事件**只归给首个超阈帧的车辆对一次**；事件分类另存

### 6.2 无效帧处理

**跑前核对 0.2.0 的无效帧逻辑**：非正净距与缺失数据**保留原值供审计**，
**不替换，也不得当作有效越阈**。

## 九、结果解释的边界（GPT 明确）

- 若某次到窗末仍未消散：**保留其固定窗计数，另报「窗尾未消散」**
- 结果只能解释为**固定窗内**的事件量，**不能说捕获了完整传播过程**
- 即使跟驰链可追溯，**只有 S0 也不能估计这些事件有多少由急刹额外造成**
