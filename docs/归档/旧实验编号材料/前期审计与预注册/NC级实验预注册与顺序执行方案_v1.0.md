# AAD 类超距交通风险作用：NC 级实验预注册与顺序执行方案 v1.0

> 状态：**冻结执行框架（2026-08-17）**
> 适用项目：AAD / `aad-traffic-risk-propagation`
> 上游数据机制：DRIFT（只读，不修改）
> 论文边界：Result 1–6 及其 Methods、Supplementary Information、Data/Code availability
> 核心原则：先校准、再冻结、后确认；先识别、后优化；全部失败都保留；不得按结果改门槛。

## 1. 本方案解决什么问题

现有 AAD 已有风险事件、局部物理传播、通信状态机和少量非局部原型，但决定性双走廊、合流迁移及其原始复算链并不完整。历史记录中的正向数字只能作为候选线索，不能作为新论文的正式证据。本方案将 E00–E19 固化为一套可证伪、可顺序验收、可复算的实验协议，使最终证据能够支撑 Nature Communications 级别的主张，而不是依赖单一场景、少量种子或一个风险指标。

这里的“达到 NC 标准”不是假设期刊规定了固定种子数。Nature Communications 没有统一的 seed 或场景数量门槛。本文采用的标准是代表性 NC 论文与 Nature 统计/报告政策共同体现的证据结构：

1. 主张与因果设计一一对应；
2. 主要终点、样本量、排除规则和失败处置在正式结果出现前冻结；
3. 有强基线、负对照、消融、独立实现和留出验证；
4. 独立重复单位与帧、消息、车辆步等嵌套观测严格区分；
5. 风险、安全、舒适性、效率和失败尾部联合报告；
6. 仿真结果有现实数据校准、分布覆盖检查和可复算产物；
7. 结论允许失败或收缩，不允许 outcome tuning。

## 2. 理论主张与可证伪预测

### 2.1 最小理论链

正式归因必须闭合以下链条：

`源风险 S_A → 风险消息 M_A → delivery → validation → adoption → 目标动作 U_B → 目标风险 R_B`

信息边只表示协议允许通信，不等于消息生成、交付或采用。采用也不等于动作变化。风险下降只有同时满足来源可追溯、处理前一致、时间隔离、动作分化和负对照无效，才可解释为信息介导的非最近邻风险效应。

主估计量保持为四格交互：

```text
Delta_NL = [R(1,1) - R(1,0)] - [R(0,1) - R(0,0)]
```

其中 `S∈{0,1}` 表示指定源风险是否存在，`C∈{0,1}` 表示指定消息是否可进入目标控制通道。负值表示风险降低，正值表示风险增加。

时间归因必须同时满足：

```text
t0 ≤ tgen ≤ tsend ≤ tdel ≤ tadopt ≤ taction < tauP
tadopt ≤ twin < twin + H < tauP
```

双走廊中只有在不存在跨走廊车辆转移、共享控制输入、跨 run 状态和通道副作用时，才允许令 `tauP=+∞`。合流中使用 `tauP` 的保守下界，整个结果窗而非仅动作时刻都必须早于物理到达。

## 3. 所有实验共用的冻结规则

### 3.1 三类预期结果

每项实验的预期结果必须属于以下一种，不得混写：

- **工程完整性预期**：例如时序单调、四格唯一差异、错误来源零采用。这类结果原则上必须 100% 通过；失败即停止。
- **零效应预期**：例如 sham channel、wrong-source、delivery-only。必须通过等效检验，不能以 `p>0.05` 代替“无效”。
- **科学效应预期**：例如 `Delta_NL<0`、通信损伤导致效应衰减。必须越过预先冻结的最小实际重要效应或剂量—响应门槛；未达到即判定该预测不成立或证据不足。

### 3.2 校准数据、正式数据和留出数据

数据分为三部分，文件级清单和 SHA-256 在首次处理前保存：

1. **Calibration**：只用于测量误差、SESOI、非劣界、场景范围、通信范围和功效方差；不用于报告正式主效应。
2. **Confirmatory**：仅在协议、代码、种子和统计脚本冻结后运行；不得回流调参。
3. **Locked holdout**：场景族、日期/地点或压力条件完全留出，所有开发决定结束后只解锁一次。

现实数据需按地点、日期或完整行程划分，不能随机拆帧。仿真需按场景族和 seed 划分，不能把同一场景的不同帧分到校准和验证两侧。

### 3.3 容差、SESOI 和非劣界的生成规则

本方案冻结“生成规则”，具体数值由 E01、E15-A、E16-A、E17-A 的 calibration 数据计算并写入 `protocol_lock_v1.1.yaml`；在该文件签名和校验和完成前，E02 及其后确认性实验不得启动。

- `delta_0`：零效应等效带。取数值实现误差、轨迹重建误差和独立分析器差异的 99% 上界中的最大值。
- `delta_R`：风险 SESOI。取 `delta_0` 与“可导致冻结控制器产生最小可执行动作变化的风险增量”二者的最大值。
- `delta_eff`：效率非劣界。由无消息控制器在独立 calibration seeds 上的自然波动和测量误差上界确定。
- `delta_comfort`：舒适性非劣界。由基线 jerk/加速度测量误差和校准变异确定。
- `delta_tail`：尾部风险 SESOI。由 E19-A 的无偏基线尾部估计误差与可接受安全风险上限共同确定。

任何门槛生成都只能使用 calibration 数据和工程约束；不得查看 confirmatory 处理效应。若无法得到稳定数值，结论是“测量尚未准备好”，不是临时指定一个更容易通过的阈值。

### 3.4 样本量与独立重复

主要独立单位为 `seed × scenario family` 的完整四格配对。frame、message、vehicle-step、同一 run 内多辆车和同一训练过程的 checkpoint 均不是独立重复。

每个主要场景族先使用 50 个独立 calibration seeds 估计配对方差和可检测性，这 50 个 seed 永不进入正式分析。由 calibration 预先给出的保守设计效应幅度 `delta_plan` 必须在运行确认性实验前写入锁定文件，且必须满足 `delta_plan > delta_R`；若达不到，说明当前机制的预期效应未越过实际重要性门槛，不能降低门槛继续运行。确认性样本量为：

```text
N_confirm = max(
  100,
  N_power(H0: Delta ≥ -delta_R, H1: Delta ≤ -delta_plan,
          alpha=0.025 one-sided, power=0.90),
  N_precision(95% CI half-width ≤
              min[0.25 × delta_R,
                  0.50 × (delta_plan - delta_R)])
)
```

方差采用 calibration 方差的单侧 95% 上置信界，以避免低估样本量。负对照单独按 TOST 对 `[-delta_0, +delta_0]` 的 90% 功效计算。稀有碰撞或硬安全事件按暴露率与单侧 95% 上限反推样本量，不能用“零碰撞”直接证明安全。100 是本项目的保守下限，不是 NC 官方规定。

### 3.5 统计分析

1. 主分析保留四格配对，以 `seed×scenario family` 为聚类层；直接检验 `S×C` 交互。
2. 主效应采用分层模型与 cluster bootstrap 95% 区间；配对 permutation/sign test 作为少假设核验。
3. 负对照采用 TOST；判定依据为 90% 区间完全落入等效带，同时报告 95% 区间。
4. 预设次要终点采用层级检验；大规模探索矩阵采用 BH-FDR，并标注为探索性。
5. 全部正式 run 进入 intention-to-run 分母。机制合格集只作为辅助分析，处理后排除不能替代主分析。
6. 报告绝对效应、标准化效应、区间、SESOI、每个 seed 原始点、正/零/负效应比例、失败分母和 Monte Carlo standard error。
7. 主要结论必须同时通过冻结分析脚本与一个独立只读分析器；不一致时以“未复现”处理。

### 3.6 统一安全与性能指标

- 追尾：事件级 `I_TTC` 为候选主要终点；DRAC、最小 TTC、冲突持续时间和碰撞为关键次要终点。
- 合流、cut-in、交叉：PET/二维冲突时间、DRAC、冲突角与碰撞；不得只用纵向 TTC。
- 瓶颈/队列：队列尾风险、传播负担、速度恢复和外溢。
- 所有场景：jerk、加速度/控制饱和、旅行时间、吞吐、平均速度、排放、误报警和不必要采用。
- 尾部：最坏 5%/1%、CVaR、碰撞/近失暴露率及单侧上界。

FHWA SSAM 的验证显示不同安全替代指标可能呈现权衡，不同仿真器也可能产生显著偏差。因此，任何“更安全”结论至少需要一个场景适配的主要指标、一个独立安全指标和硬安全事件共同支持；指标冲突必须报告，不能选择性保留有利指标。

### 3.7 版本、产物和审计

每个正式 run 至少输出：

```text
code/outputs/formal/<EID>/<protocol_version>/<run_id>/
├─ config_frozen.yaml
├─ provenance.json
├─ state.parquet
├─ emission.parquet
├─ protocol.parquet
├─ action.parquet
├─ risk.parquet
├─ audit.json
├─ run.log
└─ SHA256SUMS
```

实验级目录另含 seed/scenario 清单、失败账本、manifest、统计表、绘图数据、环境锁、commit、运行命令和 Source Data。原始输出只读；修正分析生成新版本，不覆盖旧数据。

## 4. E00–E19 逐项预注册

### E00：可复现性恢复与统一重建

**对应主张：** 全部 Result 的前置有效性。
**理论作用：** 排除 runner、时间错位、跨 run 状态、车辆 ID 和统计脚本共同制造效应。

**冻结设计**

1. 在 `code/` 中建立统一 runner、双走廊、合流、消息生命周期、统计和绘图入口；DRIFT 只读调用或复制已许可数据，不修改 DRIFT。
2. 重建历史缺失功能时以理论定义和当前测试为准，不从旧摘要反向生成“原始数据”。
3. 加入四格唯一差异、处理前一致、时间对齐、跨 run 隔离、消息时序、路径可达、车辆生命周期和统计复算测试。
4. 删除缓存后在当前环境和第二个干净环境各执行一次最小端到端包。

**主要终点：** 一条命令从冻结配置生成 run-level 原始文件、实验汇总和论文 Source Data，且所有数字可反向追溯。
**预期结果：** 两个环境生成相同纳入/排除分类、相同效应方向，数值差异落在 `delta_0` 内；所有 provenance 和校验和完整。
**硬通过门槛：** 当前回归测试与新增关键测试全部通过；manifest 覆盖率 100%；无隐藏人工步骤；第二环境复算成功；任何 run 失败均进入失败账本。
**停止/失败规则：** 任一时间顺序、状态隔离、四格唯一差异或第二环境复算失败，停止 E01 之后的正式实验。先修复并递增 E00 版本，旧输出全部作废。
**必须产物：** runner、schema、环境锁、tests、最小验证包、独立复算报告、历史数字状态表。
**资源：** 多核 CPU、独立干净环境；预计不需要 GPU。

### E01：风险指标、物理路径与数值验证

**对应主张：** Result 1。
**理论作用：** 证明 `R_j`、`taction` 和 `tauP` 是可测量量，而不是人为定义后直接使用。

**冻结设计**

1. 构造有解析答案的追尾、匀速接近、停车、换前车、负间距、侧向侵入、交叉和合流轨迹。
2. 验证 TTC、`I_TTC`、DRAC、PET、二维冲突、碰撞和事件合并。
3. 验证有路径、无路径、多路径、时变路径、右删失和已知传播速度的物理到达算法。
4. 比较 0.1、0.05、0.02 s 时间步；以 0.01 s 或解析解作为参考抽查。
5. 从 E15-A 的真实轨迹中分层抽取至少 300 个事件，由两名独立规则/审计流程核验前车、冲突类型和事件边界。

**主要终点：** 解析真值误差、路径分类准确性、时间步收敛、事件抽取 precision/recall 和独立分析器差异。
**预期结果：** 解析轨迹和物理路径全部正确；时间步变细时误差单调下降；真实事件抽取 precision 与 recall 均不低于 0.95；0.05 与 0.02 s 的主要指标差异落入 `delta_0`。
**硬通过门槛：** 解析/path truth 100% 通过；无处理依赖的指标定义；事件 precision/recall ≥0.95；主结论在两个时间步和至少两个适配风险指标上方向一致；`delta_0`、`delta_R` 规则成功锁定。
**停止/失败规则：** 任一核心解析案例失败或时间步改变主效应方向，禁止 E02。若不同指标冲突，先限定风险类型并指定单一主终点，不能选择最有利指标。
**必须产物：** analytic fixtures、metric validation、path truth set、人工审计表、`protocol_lock_v1.1.yaml` 初稿。
**资源：** CPU；依赖 E00、E15-A。

### E02：物理断开双走廊主四格确认实验

**对应主张：** Result 2 的核心主效应。
**理论作用：** 在 `tauP=+∞` 的结构隔离条件下识别指定消息的增量风险效应。

**冻结设计**

1. `S×C` 四格完整配对；四格共享背景交通、初始状态、seed 和非处理控制逻辑。
2. 场景按目标基础风险、交通需求、源—目标事件相位、人驾参数和目标位置分层；使用空间填充抽样，避免全笛卡尔无效堆量。
3. 设置独立的域内 confirmatory block 和组合留出 block，两个 block 都在运行前冻结。
4. 消息是唯一跨走廊输入；禁止共享随机状态、控制状态、文件缓存和车辆迁移。

**主要终点：** 事件级标准化风险负担的 `Delta_NL`。
**关键次要终点：** DRAC/最小 TTC、碰撞、jerk、旅行时间、吞吐、消息链完成率。
**预期结果：** 两个确认 block 的 `Delta_NL` 均小于 `-delta_R`；处理前一致；无物理路径；C=0 零采用；S=0 无指定源风险消息；没有预设场景族出现实际重要的风险增加。
**硬通过门槛：** 两个 block 的单侧 95% 上界均 `< -delta_R`；拓扑与共享状态审计 100% 通过；全部被归因 trial 的消息先于动作；碰撞率上界不劣于 local-only；预设亚组中无区间完全高于 `+delta_R` 的伤害信号。
**停止/失败规则：** 任一 block 未越 SESOI，则 H2 不通过；不得合并 block、换窗口或删除正效应 seed。若仅一个场景族成立，Result 2 必须限定在该域并重新评估投稿主线。
**必须产物：** 四格原始数据、每 seed 效应、拓扑证明、处理前一致表、异质性与失败分母。
**资源：** CPU 集群；样本量按 3.4 计算；依赖 E00、E01 和 Calibration Lock。

### E03：强竞争基线与信息增量价值

**对应主张：** Result 2，并为 Result 4 的控制价值排除简单解释。
**理论作用：** 区分“远端风险语义有增量价值”与“任何提前刹车都降低风险”。

**冻结设计**

比较 local-only、只用本地历史的 predictive controller、always-cautious、oracle、remote raw state、remote risk summary、action-matched replay 和 bandwidth/computation-matched sham。所有方法使用相同目标、窗口、背景交通和控制边界；always-cautious 的动作量与消息方法校准到可比较的安全水平。

**主要终点：** 相对 local predictive controller 的风险增益，以及相对 always-cautious 的风险非劣与效率/舒适性优势。
**预期结果：** risk-summary 相对 local predictor 的风险改善越过 `delta_R`；与 always-cautious 相比安全不劣，且至少一项效率或舒适性改善越过相应 SESOI；sham 等效于零；oracle 保持合理上界。
**硬通过门槛：** 上述三项同时通过；action-matched 分析证明风险差异由动作路径解释而非统计副作用；remote raw state 不得因更大带宽获得未匹配优势。
**停止/失败规则：** 若 local predictor 消除增量效应，删除“远端信息不可由本地预测替代”的主张；若 always-cautious 同样安全且代价不更高，删除信息语义/精准采用的控制价值主张。
**必须产物：** 基线冻结参数、Pareto 点、动作匹配审计、带宽与计算量表。
**资源：** CPU；依赖 E02。

### E04：独立实现与独立复算

**对应主张：** Result 2 的软件独立性。
**理论作用：** 排除单一 runner、状态机或汇总器的系统性错误。

**冻结设计**

1. 独立离线分析器仅读取原始 state/protocol/action，不调用在线汇总代码。
2. 建立最小第二 runner；共享理论 estimand 和冻结场景，不复制主 runner 的状态机代码。
3. 对时间错一仿真步、跨 run 通道污染、陈旧车辆 ID、错误路径、渗透率解析和行错位进行 mutation tests。

**主要终点：** 纳入分类一致率、效应差异、时刻差异和第二实现的 E02 复制结果。
**预期结果：** 两个分析器分类一致率 ≥99.9%，全部差异可追溯；效应差异落在 `delta_0`；第二 runner 在锁定复制集上越过 `-delta_R`。
**硬通过门槛：** mutation tests 100% 能发现注入错误；第二 runner 独立通过核心方向与 SESOI；关键时间戳差异不超过一个仿真步。
**停止/失败规则：** 第二实现不复现时，E02 只算软件内部现象，停止机制和泛化实验，先定位实现差异。
**必须产物：** independent analyzer、second runner、mutation report、差异账本。
**资源：** CPU；依赖 E02。

### E05：消息生命周期与作用链闭合

**对应主张：** Result 3。
**理论作用：** 验证 `S_A→M_A→delivery→validation→adoption→U_B→R_B` 的逐 trial 顺序。

**冻结设计**

逐消息记录 event、generation、send、drop/delay、delivery、source/time validation、adoption、action divergence 和 risk divergence；在线日志与离线状态重建相互核验。采用资格在处理结果前定义，每次拒绝必须有唯一 reason code。

**主要终点：** 生命周期完整率、时序违规率、eligible→adoption→action 的转化率和动作后风险变化。
**预期结果：** 所有记录满足单调时间顺序；理想通道中所有合格消息均被采用或有可复算的安全拒绝原因；至少 90% 的合格 treated trials 在窗口内出现动作分化；风险变化不早于动作分化。
**硬通过门槛：** 时序和 ID 完整性 100%；在线/离线关键时刻在一个仿真步内一致率 ≥99.9%；无“先有风险结果、后有动作”的归因；主效应在 intention-to-run 集仍通过 E02。
**停止/失败规则：** 任何系统性时序倒置、未解释采用或日志缺口均暂停机制归因。动作分化率低于 90% 时，结论收缩为消息交付/采用协议，不宣称稳定动作机制。
**必须产物：** trial timeline、转化漏斗、reason-code 表、在线/离线一致性报告。
**资源：** CPU；依赖 E02、E04。

### E06：负对照与证伪矩阵

**对应主张：** Result 3 的替代解释排除。
**理论作用：** 证明来源、目标、时效、语义和采用环节是必要条件。

**冻结设计与预期签名**

| 负对照 | 冻结预期 |
|---|---|
| wrong-source | 可交付，来源校验失败，采用精确为 0，效应等效于 0 |
| wrong-target | 目标校验失败，采用精确为 0，效应等效于 0 |
| future/wrong timestamp | 时序校验失败，采用精确为 0，效应等效于 0 |
| expired/stale | 新鲜度校验失败，采用精确为 0，效应等效于 0 |
| delivery-only | 有交付，无采用，效应等效于 0 |
| random payload | 无事件特异性效应，风险与动作效应等效于 0 |
| matched-rate pseudo-source | 控制消息频率和共同时间趋势后效应等效于 0 |
| S=0 channel-on | 通道运行副作用等效于 0 |
| shuffled event-message pairing | 错配消息效应等效于 0 |
| message after physical arrival | 归类为不可归因，不进入非局部效应成功数 |

**主要终点：** 每类对照的 adoption、action 和 `Delta_NL`。
**预期结果：** 确定性拒绝对照零采用；随机/sham 类对照的 90% 区间完全位于 `[-delta_0,+delta_0]`；晚到消息无信息先行归因。
**硬通过门槛：** 十类对照全部符合各自签名；TOST 通过；任何确定性拒绝不得出现一次采用。
**停止/失败规则：** 任一对照出现稳定同向效应，暂停 H2/H4 解释并检查共享状态、时间趋势、统计泄漏和通道副作用；不得把该对照改为探索性后继续主张。
**必须产物：** 对照矩阵、等效检验、逐层故障定位、全部异常消息。
**资源：** CPU；每类样本量按等效功效计算；依赖 E05。

### E07：通信剂量—响应与安全失效边界

**对应主张：** Result 3 与 Result 6。
**理论作用：** 检验有限传输时延和消息新鲜度是作用域条件，而非事后解释。

**冻结设计**

1. E16-A 给出可配对真实通信的时延、丢包、连续性和距离联合分布；其中心 90% 定义经验运行区间。
2. 先用空间填充设计筛选固定/随机时延、抖动、独立/突发丢包、更新率、年龄、范围、渗透率、转发跳数和负载的主交互，再在转折区确认。
3. 经验中位条件、90% 边界条件和明确超出边界的 stress 条件分别冻结；确认性数据不用于重选转折点。

**主要终点：** `Delta_NL` 对采用时消息年龄的剂量—响应，以及超龄拒绝后的安全退化。
**预期结果：** 经验中位和 90% 边界内仍有负向效应；随着有效消息年龄增加，效应向零衰减；超过冻结 freshness threshold 后 adoption 为 0，系统退化到 local-only 且无实际重要伤害。
**硬通过门槛：** 经验中位条件上界 `<-delta_R`；90% 边界至少上界 `<0` 且无 `>+delta_R` 伤害；年龄—效应衰减斜率方向正确且区间不跨 0；超龄条件与 local-only 等效。
**停止/失败规则：** 现实范围内失效则理论限制于更窄通信域；任何 stale/partial delivery 产生稳定伤害时停止部署价值主张，先修复 fail-safe。若 E16 无法识别真实时延/丢包，E07 只能作为合成鲁棒性，不能称现实通信验证。
**必须产物：** DOE 设计、经验通信区间、剂量曲线、失效阈值、风险—效率—通信 Pareto。
**资源：** CPU 集群；依赖 E06、E16-A。

### E08：逐模块机制消融

**对应主张：** Result 3 与 Result 6。
**理论作用：** 检验各模块的必要性和其对应的可观察失败签名。

**冻结设计**

消融来源验证、新鲜度门控、事件资格、adoption、风险语义/强度、动作映射、安全盾、本地—远端融合、消息聚合、多源冲突处理和路径时序检查。每项消融均预先写出“应影响哪一级、不得影响哪一级”，并跨双走廊、合流和一个留出风险场景运行。

**主要终点：** 生命周期断点、主效应、负对照泄漏、碰撞/尾部、jerk 和效率。
**预期结果：** 关闭 adoption 或替换为 rate-matched 无语义 payload 时主效应等效于零；移除 source/freshness validation 时对应负对照选择性失效；移除安全盾时尾部风险恶化但消息交付链不改变。
**硬通过门槛：** 完整模型继续通过 E02/E06；三项核心签名（adoption、语义、source/freshness）全部符合；不同消融的失败层级可区分。
**停止/失败规则：** 若移除某理论必需模块不改变任何结果，该模块不得继续被写成机制必要条件；若多个消融产生相同签名，Result 3 降级为不可区分机制。
**必须产物：** 预期签名表、消融主/次终点、故障层级图、所有反常结果。
**资源：** CPU，学习控制器消融可用 GPU；依赖 E06。

### E09：物理连通多合流几何迁移

**对应主张：** Result 4。
**理论作用：** 在恢复物理路径后检验信息领先是否仍可产生闭环收益。

**冻结设计**

至少覆盖短/中/长加速车道、不同汇入角/限速、单/多车道、主线与汇入需求、目标位置及人驾分布。资格规则只使用源事件形成、处理前一致和无预处理碰撞，不查看处理后风险。早期 v1 失败、历史 v2 记录和新确认批次分别保存，不合并覆盖。

**主要终点：** 合流适配风险指标的 `Delta_NL`，且整个结果窗早于 `tauP` 保守下界。
**关键次要终点：** PET/DRAC/碰撞、jerk、吞吐、旅行时间、排放和队列外溢。
**预期结果：** 总体与留出几何均为负；至少三个独立几何族方向一致；信息领先裕度越大，收益越稳定；风险下降不以不可接受的效率或舒适性损失换取。
**硬通过门槛：** pooled 与 locked holdout 的上界均 `<-delta_R`；至少 3 个几何族上界 `<0`，其中至少 2 个 `<-delta_R`；全部归因 trial 的窗口早于 `tauP`；无亚组实际重要伤害。
**停止/失败规则：** 未满足时，Result 4 改写为几何特定或失败边界。不得用处理后风险筛资格 seed，不得删除早期失败批次。
**必须产物：** 几何定义、outcome-blind 资格日志、四格与时间轴、安全—效率结果、失败几何。
**资源：** CPU 集群；依赖 E07、E08、E10 的校准方法。

### E10：物理到达与时间竞争独立验证

**对应主张：** Result 4 的归因条件。
**理论作用：** 证明动作与整个风险窗口先于普通交通传播。

**冻结设计**

用消息屏蔽 counterfactual、已知冲击响应和时序可达图三种独立方法估计 `tauP`。人工注入已知传播速度与路径的扰动做校准；右删失用区间/生存方法，不把“未观察到”直接写成无限远。

**主要终点：** `tauP` 估计误差、三方法一致性、信息领先裕度 `L=tauP_lower-(twin+H)`。
**预期结果：** 已知传播校准的中位误差不超过一个仿真步、95% 误差不超过两个仿真步；三方法的保守区间在至少 95% trial 中重叠；所有被归因 trial 的 `L>0`。
**硬通过门槛：** 校准误差与方法一致性达标；归因 trial 的动作和窗口 100% 早于 `tauP` 保守下界；`taction≥tauP` 全部标为不可归因。
**停止/失败规则：** 物理到达估计不稳定时，E09 只能报告控制相关性，不能报告信息先行因果归因。改变动作容差或窗口导致主要分类改变时，必须先解决测量定义，不能挑一个版本。
**必须产物：** propagation truth set、三估计器、逐 trial 时间轴、右删失与敏感性表。
**资源：** CPU；方法校准在 E09 正式运行前完成。

### E11：跨控制器复现

**对应主张：** Result 6。
**理论作用：** 检验效应是否只由一个透明规则控制器的特殊实现造成。

**冻结设计**

比较透明规则、带安全约束的 MPC/CBF-MPC、学习控制器加独立安全盾。三者接收相同消息语义与本地观测，并先在无消息 calibration seeds 上匹配基线安全和效率。学习控制器至少 10 个独立训练 seeds；训练、选择、开发评估和正式评估 seeds 分离；按冻结验证规则选择 checkpoint，报告全部训练 seeds，不只挑最佳模型。

**主要终点：** 各控制器的标准化 `Delta_NL` 与控制器×消息交互。
**预期结果：** 至少两类原理不同的控制器（必须包含一种非规则控制器）越过各自 `delta_R`；控制器间异质性可由动作余量、约束激活或信息利用解释。
**硬通过门槛：** 至少 2/3 控制器通过，且任一控制器均无实际重要风险伤害；学习控制器的结论对训练 seed 分布成立，不依赖单一 checkpoint。
**停止/失败规则：** 仅规则控制器通过时，论文明确限定为特定透明采用协议；非规则控制器出现伤害时停止一般控制器主张并保留失败。
**必须产物：** 基线匹配报告、训练曲线/全部 checkpoints、评估矩阵、控制异质性。
**资源：** CPU+GPU；依赖 E02–E10。

### E12：跨风险类型复现

**对应主张：** Result 6。
**理论作用：** 检验机制是否局限于纵向前车急刹和 TTC 指标。

**冻结设计**

四个主风险族为前车急刹/追尾、cut-in/lane-change、合流让行和瓶颈/队列尾；可增加交叉口侧向侵入。每类使用场景适配主指标，统一比较标准化效应。至少一个风险族完全留出，不参与消息编码和控制调优。

**主要终点：** 各风险族标准化风险负担的四格交互。
**预期结果：** 至少三类风险（含留出风险）出现负向效应；适配安全指标与硬事件方向一致；不存在靠原始量纲混合制造的总体效果。
**硬通过门槛：** 至少 3/4 风险族上界 `<0`，其中至少 2 类 `<-delta_R,type`，且留出风险上界 `<0`；无风险族出现区间完全高于 `+delta_R,type`。
**停止/失败规则：** 仅追尾成立时，删除普遍风险传播主张并限定为远端制动风险；任何类型出现伤害均公开为禁用域。
**必须产物：** 风险类型协议、适配指标验证、标准化效应、留出预测和禁用域。
**资源：** CPU/GPU；依赖 E11。

### E13：跨拓扑、需求和驾驶行为的边界模型

**对应主张：** Result 6。
**理论作用：** 将“何时有效”转化为可预测边界，而不是罗列大量场景。

**冻结设计**

信息图覆盖单源、冗余/冲突多源、星形、链式、多跳、社区/motif 和动态断连；物理图覆盖断开、串行跟驰、合流、瓶颈、环路/网格；交通覆盖自由流、临界、拥堵、需求波动、渗透率和多种人驾模型。边界模型只使用理论变量：信息领先裕度、消息年龄、来源可靠度、目标可控余量、物理传播速度和控制约束激活率。

**主要终点：** 对留出场景“有效/无效/有害”类别及效应量的预注册预测准确度。
**预期结果：** 较大的信息领先裕度、较新消息和较高可控余量对应更稳定收益；模型能预测留出拓扑的方向与失败边界。
**硬通过门槛：** 留出类别 balanced accuracy ≥0.80；效应量预测区间覆盖率 85%–95%；校准斜率 0.8–1.2；不存在未预测的系统性有害区域。
**停止/失败规则：** 达不到时只报告经验场景矩阵，不声称形成一般边界规律；发现新有害域立即加入禁用域，不能以模型外点删除。
**必须产物：** 理论特征定义、训练/留出拓扑、预测文件（结果解锁前生成）、校准与失败图。
**资源：** CPU 集群；依赖 E11、E12、E17-A。

### E14：第二阶段安全约束控制优化

**对应主张：** Result 4/6 的应用价值；不参与第一阶段因果识别。
**理论作用：** 在 H2–H7 已通过后，将可识别信息效应转化为安全—舒适—效率收益。

**冻结设计**

比较规则、MPC/CBF-MPC 和学习策略的 Pareto 前沿。四类核心量为平均风险、动作与舒适性、通行效率和 CVaR 尾部风险，硬安全为不可放松约束；吞吐、排放、误报警和不必要采用作为预先指定的次要运行指标，不参与事后策略选择。训练/调参只能使用 development 与 E19-A 发现集；最终评估使用 E19-B 和场景留出集。always-cautious、local-only 和 oracle 为固定参照。

**主要终点：** 预先选定策略相对 local-only 的风险改善，以及相对 always-cautious 的效率/舒适性改进。
**预期结果：** 选定策略风险改善越过 `delta_R`；对 always-cautious 安全非劣，并在效率或舒适性至少一项越过相应 SESOI；最坏 5%/1% 风险不恶化。
**硬通过门槛：** 三项同时通过；碰撞/硬安全事件的上置信限不劣于基线；Pareto 选择规则在 holdout 解锁前固定。
**停止/失败规则：** 风险收益依赖不可接受效率/jerk 代价时，删除“有效控制”主张；优化失败不推翻 E02 的识别结果，但 Result 4/6 应降级。
**必须产物：** 训练协议、Pareto 前沿、选择规则、holdout 结果、全部失败策略。
**资源：** CPU+GPU；依赖 E11–E13 和 E19-A。

### E15：真实轨迹风险测量与传播锚定

**对应主张：** Result 5；并为 E01、E17 提供 calibration。
**理论作用：** 验证风险测量和普通物理传播背景，不用于证明真实车辆采用远端消息。

**冻结设计**

全量处理 NGSIM 多地点/时段、pNEUMA 地图匹配后的多方向交通，以及取得许可后的 INTERACTION 多场景。按地点/日期/场景分 calibration 与 locked holdout；统一前车/冲突匹配、episode、TTC/DRAC/PET 和不确定性规则。帧嵌套于车辆/事件，统计单位为事件、车辆和场景。

**主要终点：** 事件抽取准确性、真实风险/传播特征分布和跨数据集复现。
**预期结果：** 至少两个独立地点或数据集产生可审计的风险事件分布；极端值能区分真实冲突、轨迹误差和匹配错误；普通物理传播时间/速度可估计。
**硬通过门槛：** 分层人工审计 precision/recall ≥0.95；所有单位、坐标和匹配不确定性可追踪；至少两个独立数据源支持同方向的测量有效性；不把帧当独立样本。
**停止/失败规则：** 地图匹配或前车识别未达标的数据集只作字段审计；真实数据不能支持 adoption 时，Result 5 明确止于测量/接收层，不拼接成闭环因果链。
**必须产物：** 数据清单/checksum、calibration/holdout split、事件表、QA、测量与传播分布。
**资源：** 大内存 CPU/高速存储；A 阶段在 E01 前完成，B 阶段在协议冻结后解锁。

### E16：真实通信发送—接收配对

**对应主张：** Result 5，并为 E07 提供经验区间。
**理论作用：** 验证消息可达性、时延、丢包和连续性，不越界声称控制采用。

**冻结设计**

在 SPMD 中关联 Packet、发送侧 BSM 与 `RV_RX`，完成设备、行程、远车、消息计数和时钟校正。先用 calibration 行程建立匹配规则，再锁定到 holdout 行程；只在有发送机会分母时估计丢包。

**主要终点：** Tx/Rx 唯一匹配率、机会条件丢包、时延、连续性、距离和时钟残差。
**预期结果：** 能形成高覆盖低歧义的消息级配对，并给出供 E07 使用的经验联合分布；不同距离/负载层呈合理变化。
**硬通过门槛：** 可配对机会覆盖率 ≥95%，歧义匹配 <1%，时钟校正残差的 95% 分位不超过一个记录采样间隔；否则不得报告消息级时延/丢包。
**停止/失败规则：** 配对不达标时，只保留接收连续性结论；不得把 `RV_RX` 状态断点解释为丢包，也不得声称 adoption。
**必须产物：** 匹配规则、机会分母、时钟校正、经验通信区间和不可观察字段清单。
**资源：** 大内存 CPU/流式处理；A 阶段在 E07 前完成。

### E17：仿真—真实分布覆盖与模型可信度

**对应主张：** Result 5，并约束 Result 6 的外推。
**理论作用：** 证明仿真场景覆盖真实风险和交通状态，而不是手工挑选易出正结果的域。

**冻结设计**

比较速度、间距、相对速度、减速度、事件持续时间、需求、冲突类型、传播时间和通信条件。使用真实—真实分割建立自然数据集差异基准，再比较仿真—真实差异。校准集仅用于场景生成器调节；holdout 只解锁一次。

**主要终点：** 核心特征的 sim-real 距离、真实风险 strata 覆盖率和未覆盖区域。
**预期结果：** 仿真—真实差异不大于真实地点/日期之间的合理差异；确认实验覆盖绝大多数真实冲突层，同时明确少数外推区。
**硬通过门槛：** 核心联合特征的 sim-real 距离不超过 real-real 距离的 95% 分位；至少 90% 真实冲突 strata 落入仿真支持；holdout 上不出现系统性极端偏移。
**停止/失败规则：** 不达标时先扩展/重校准场景生成器，受影响的 E11–E13 正式矩阵不得启动；无法覆盖的域标为论文外推禁区。
**必须产物：** feature schema、real-real 基准、sim-real coverage、未覆盖区和场景修订记录。
**资源：** CPU/RAM；A 阶段在 E13 前，B 阶段在模型冻结后。

### E18：硬件在环或同步混合现实闭环

**对应主张：** Result 5/6 的高价值外部闭环证据。
**理论作用：** 缩短纯 SUMO 消息机制与真实控制栈之间的距离。

**冻结设计**

使用真实控制器/Autoware/CARLA-SUMO 或封闭场地低速平台，覆盖急刹、cut-in、合流和误报警；记录生成、网络、校验、采用、控制命令与车辆动力学。注入 E16/E07 验证区间内的时延、抖动、突发丢包、传感噪声和执行延迟。至少一个场景完全留出。

**主要终点：** 端到端闭环 `Delta_NL`、实际执行延迟和适配安全指标。
**预期结果：** 完整消息—动作—风险链在真实控制栈中复现；端到端延迟落在 E07 已验证域；风险改善不以舒适/效率或硬安全代价换取。
**硬通过门槛：** pooled 与留出场景上界 `<0`，pooled `<-delta_R,HIL`；生命周期日志完整率 100%；封闭场地零物理碰撞/越界；硬安全事件上限不劣于 local-only。
**停止/失败规则：** 仅仿真动力学而无真实控制栈时只称 HIL/混合现实，不称道路实证；链条或执行时延不达标时删除现实闭环主张。
**必须产物：** 硬件/软件版本、时钟同步、端到端日志、视频/轨迹、安全案例和失败记录。
**资源：** 独立控制机、网络仿真、可选车辆/试验场；依赖 E14、E16、E19-B。

### E19：对抗稀有事件与尾部可靠性

**对应主张：** Result 6，并为 E14 提供 hardening 数据。
**理论作用：** 主动寻找理论和控制器的失效域，避免均值改善掩盖尾部灾难。

**冻结设计**

E19-A 使用重要性采样或生成器在现实动力学/分布约束内发现极端 cut-in、急刹、多源冲突消息、低附着、长延迟和高密度组合。发现集进入 E14 开发。随后冻结独立 E19-B stress-test suite，生成规则、随机流和权重均锁定，不再用于训练。重要性权重在小规模自然抽样上校准。

**主要终点：** 碰撞/近失暴露率、最坏 1%/5%、CVaR、失败模式覆盖率和加权估计偏差。
**预期结果：** E19-A 能发现基线真实失败，而不是返回“全部安全”；E14 后的方法在 E19-B 上降低尾部风险并保持估计校准；所有场景保持现实可实现性。
**硬通过门槛：** E19-A 在预设预算内发现至少一个可复现且动力学可实现的基线失败族，否则判定生成器无效；E19-B 的 CVaR/尾部风险改善越过 `delta_tail`；碰撞率单侧上界低于基线并满足安全上限；自然抽样校准无显著偏差。
**停止/失败规则：** 不现实的对抗样本不进入证据；同一 stress suite 上训练并测试的结果作废；若优化后尾部风险不降，删除强安全/鲁棒部署主张，并公开 failure zoo。
**必须产物：** 生成器、现实约束、发现集、冻结测试集、权重校准、failure zoo 和完整尾部结果。
**资源：** GPU+大量 CPU rollout；A 阶段在 E14 前，B 阶段在 E14 冻结后。

## 7. 协议变更与“不返工”规则

1. **E00 前**可修正文档错误，但必须记录变更原因。
2. **Calibration Lock 前**可基于 calibration 数据填入数值门槛和样本量；不得查看 confirmatory 效应。
3. **任一确认实验启动后**，该实验的主终点、SESOI、种子、排除、窗口和分析脚本不得修改。
4. 必须变更时创建 amendment，说明触发原因、受影响实验和旧数据处置；旧批次不得与新协议静默合并。
5. 软件 bug 修复后，所有可能受影响的正式 run 全部重跑；不能只补失败 cell。
6. 任何未预注册分析均标记 exploratory，不用于替代失败的 primary outcome。
7. 历史 O01–O16 只作 provenance、pilot、失败或候选记录；除非在当前冻结协议下复算，否则不进入正式主统计。

## 10. 冻结结论

本方案从 v1.0 起作为 AAD 后续实验的唯一顺序执行依据。第一项工作不是直接扩大 seed，而是完成 E00；E00 通过后处理现实 calibration 数据，再由 E01 生成 `protocol_lock_v1.1.yaml`。只有 v1.1 锁定实际容差、SESOI、样本量和数据分割后，才允许启动 E02。

“达不到就不行”的正式含义是：每个实验必须达到其预注册门槛，未达到即停止该主张、修复前置测量或按规则收缩理论；绝不通过事后更换种子、窗口、指标、场景或阈值制造通过结果。这样即使出现零结果或失败结果，也不会造成无意义返工，而会直接转化为理论边界和论文中可审计的证据。

## 11. 实际执行第一原则

以下原则自 2026-08-17 起与实验门槛具有同等约束力，后续任何实现、调试和算力安排都不得绕过。

### 11.1 理论—实验一致性优先

1. 理论定义、因果链、estimand、时间约束和适用域是实验设计的上位规格；不得因为实现困难而删除必要环节、替换主估计量或放宽时间归因。
2. 每个实验启动前必须填写“理论条件—可观测变量—实现位置—验收测试”四列映射。没有实现映射的理论条件视为未实现，不得靠文字解释补足。
3. 实验允许证伪理论，但不允许实验设计偏离理论后仍声称验证了理论。理论预测未通过时按预注册规则收缩或否定主张，不修改数据追求正结果。
4. 若理论要求在现有软件、数据、硬件或权限下确实无法实现，立即停止受影响实验，记录已经尝试的方法和准确阻断条件并告知用户；不得私自换成更容易但回答不同问题的实验。
5. 任何理论定义本身需要修改时，先形成独立 amendment，说明科学理由和受影响结果，经用户确认后才修改；实现便利不构成修改理论的理由。

### 11.2 严格顺序和范围控制

1. 同一时间只推进当前 Gate；前一 Gate 未通过，不预跑后续正式矩阵，不用后续结果倒逼前置规则。
2. 当前任务只实现该实验的冻结要求和直接依赖，不顺手增加无关模型、指标、可视化或大规模参数搜索。
3. 探索性诊断必须单独标记，不得混入 confirmatory 输出或改变主分析。
4. 算力不设为删减科学要求的理由，但先用最小测试、smoke 和 calibration 验证实现，再按锁定样本量放大。

### 11.3 完整记录和可续接性

1. 每项实验在对应阶段目录下保存唯一执行记录，包含理论映射、版本、命令、环境、输入、输出、失败、修复、测试和 Gate 决定；阶段目录由 `docs/论文实验推进/总计划.md` 统一索引。
2. 每次运行保存 code commit、工作树状态、环境锁、配置/数据/seed manifest 及 SHA-256；原始产物只读，修复后生成新版本。
3. 命令记录必须包含工作目录、完整命令、开始/结束时间、退出码和关键输出；失败命令与成功命令同等保留。
4. 所有实现变更采用测试先行：先记录预期失败，再实现最小修复并记录通过证据。没有 RED 证据的新行为不得视为已验证。
5. 每次结束工作前更新当前状态、下一条唯一动作和阻断项，使后续续接无需重新检索历史文件。
