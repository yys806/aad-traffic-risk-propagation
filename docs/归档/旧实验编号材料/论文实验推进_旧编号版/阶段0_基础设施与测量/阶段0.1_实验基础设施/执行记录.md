## 2. 理论—实现约束

E00 不检验正向风险效应，但它必须保证后续理论量可以被可信实现：

| 理论条件 | E00 必须提供的实现证据 | 不满足时的处理 |
|---|---|---|
| 四格仅 `S` 与 `C` 不同 | 冻结配置差异审计与自动测试 | 停止 E02 |
| 处理前一致 | state/action 的配对前缀比较 | 停止 E02 |
| 生命周期单调 | event→send→delivery→adoption→action 时间测试 | 停止 E05 |
| 无跨 run 污染 | 每 run 独立状态、缓存和随机源测试 | 全部正式输出作废并重跑 |
| 物理路径和 `tauP` 可复算 | 独立离线路径/时间分析入口 | 停止 E09/E10 |
| `Delta_NL` 可独立复算 | 原始 state/protocol/risk 到 effect 的只读分析器 | 停止科学解释 |
| 全部数字可追溯 | config、commit、environment、manifest、checksum | 不进入投稿证据 |

## 3. 冻结 E00 验收目标

1. 从删除派生缓存后的冻结输入，一条命令生成最小 run-level 产物和汇总。
2. 每个 run 具有 config、provenance、state、protocol、action、risk、audit、log 和 checksum；未适用字段必须显式说明，不能静默缺失。
3. 当前环境与第二干净环境的纳入分类、效应方向一致，数值差异在 E01 后锁定的容差内。
4. 时间错位、跨 run 污染、陈旧 ID、错误路径和错误四格差异的 mutation tests 能稳定失败。
5. 历史双走廊/合流缺失资产只标记为 unverified，不从摘要伪造原始包。
