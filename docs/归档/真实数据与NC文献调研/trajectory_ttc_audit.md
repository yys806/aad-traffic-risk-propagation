## NGSIM 计算口径

官方 US-101 元数据对相关字段的定义是：`Preceding` 为同车道前车 ID，0 表示无前车；`Space_Headway` 是本车前部中心至前车前部中心的距离，单位英尺；`v_Length` 为车辆长度，单位英尺；`v_Vel` 为速度，单位英尺每秒。

对本车 `i` 和其报告前车 `j`，仅在两者的 `Global_Time` 完全相同且 ID 成功匹配时计算：

```text
g_ij = (Space_Headway_i - v_Length_j) * 0.3048
u_ij = (v_Vel_i - v_Vel_j) * 0.3048
TTC_ij = g_ij / u_ij
```

其中：

- `g_ij` 是本车前部至前车尾部的净间距，单位米；
- `u_ij` 是接近速度，单位米每秒，正值表示本车正在接近前车；
- 代码同时保留 `leader_rel_speed_mps = v_leader - v_follower`，因此该字段为负时才表示接近，与项目现有仿真字段符号一致；
- TTC 有效条件为：`Preceding != 0`、同一时刻能匹配前车、`g_ij > 0`、`u_ij > 0.001 m/s`；
- 无前车、前车未匹配、净间距非正或没有接近时，`ttc_valid=False` 且 `ttc_s=inf`，不会被计入低 TTC 分母。

## US-101 真实片段结果

输入为 `0750am-0805am/trajectories-0750am-0805am.csv` 的前 200,000 行，覆盖 443 辆车、2,142 个帧号和 214.1 秒。该片段不是随机样本，也不是完整 15 分钟窗口；以下数字只用于验证计算链，不能当作总体发生率。

| 审计项 | 行数 |
|---|---:|
| 总行数 | 200,000 |
| 未报告前车 | 13,238 |
| 报告前车 | 186,762 |
| 报告前车但同帧未匹配 | 629 |
| 成功匹配但净间距非正 | 234 |
| 净间距为正但未接近 | 113,717 |
| 有效 TTC | 72,182 |
| 有效 TTC < 2 s | 390 |

在有效 TTC 内，`TTC < 2 s` 占 `390 / 72,182 = 0.540%`。TTC 中位数为 22.673 s，1% 分位数为 2.524 s，最小值为 0.0204 s。

最小 TTC 来自极小净间距：该行 `Space_Hdwy=76.49 ft`，匹配前车长度约 `76.10 ft`，相减后净间距仅约 `0.119 m`。这可能来自真实临近、车辆长度/前车标识异常或轨迹重建误差，必须回看连续帧和场景位置；不能把单帧极小 TTC 直接称为真实碰撞或近失事件。正式统计前至少需要增加连续帧持续时间、轨迹跳变和 lane/leader 切换审计。

## 当前不能说明什么

1. NGSIM 的 390 个低 TTC 帧不是 390 个独立冲突事件；需要按车辆和时间合并事件，并报告持续时间与事件数。
2. 本次只验证 US-101 一个窗口的前 200,000 行，不能代表 US-101 全窗口、其他 NGSIM 道路或不同交通状态。
3. pNEUMA 的 WGS84 坐标和车辆状态不足以直接得到同车道 leader。未经地图匹配和方向约束的欧氏最近邻不能替代前车关系。
4. NGSIM 与 pNEUMA 都不能观察显式消息或控制器采用，因此它们只能验证轨迹风险和物理传播侧，不能验证类超距作用的完整因果链。
5. 当前结果没有把 NGSIM 的低 TTC 帧与项目中的区域平均 TTC 冲突负担 `B_TTC` 或目标车辆积分负担 `I_TTC` 等同，也没有跨实验比较绝对值。

## 下一步

1. 在 NGSIM 四类道路上按完整时间窗分块运行，先做 lane/leader 连续性和极端 TTC 质量审计，再固定事件合并规则与阈值。
2. 把有效 TTC 转成车辆-时间层风险序列，分别实现低 TTC 帧率、事件率和持续时间，不与仿真 `B_TTC`、`I_TTC` 混用名称。
3. pNEUMA 先完成道路地图匹配、行驶方向和车道级排序的验证集；只有人工抽查通过后，才计算 leader-aware TTC。
4. 在 NGSIM 中先估计物理风险传播的时间尺度和空间衰减；真实轨迹数据提供外部基线，信息作用仍需 SPMD 消息配对或专门通信实验识别。
