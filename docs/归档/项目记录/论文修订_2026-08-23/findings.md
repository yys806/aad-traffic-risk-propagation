# 审查发现

1. `(9d)--(9m)` 含处理后消息采用、动作分化和时间结果，却被用于筛选主分析集合，违反 intention-to-run。
2. `\pi^{\mathsf Z}` 尚未直接定义 `Z_{q,j}(t)`，消息采用状态与控制信息向量之间缺少数学连接。
3. P1 中消息 `q` 未完整绑定源事件、源车辆、目标车辆和处理格。
4. `|\Delta^{\mathsf{NL}}|` 的双侧存在性判定与预注册的负向安全收益判定混用。
5. Result 4 所需的连通场景信息先行条件没有形成独立的 Stage II 前置资格。
6. 预注册 `P1--P8` 与正文 `\mathcal P_1,\mathcal P_2` 重名。
7. `M_{j,t}`、`\mathcal V_{\mathsf{valid}}`、`j_{j,t}` 和 CVaR 参数 `\alpha` 存在语义或符号问题。
8. P2 与 E14 的 Pareto、吞吐、排放和误报警评价尚未完全对齐。

## 已确认优点

- Result 1--6 的宏观证据顺序合理。
- 两阶段职责边界正确。
- 四类代价在 P2 说明用途、在后续指标小节给出数学定义的组织方式正确。
- 主稿可由 XeLaTeX 编译，交叉引用当前有效。

## 修复结果

1. **上下文一致性**：Stage I 主效应改为 intention-to-run；消息来源、交付、校验、采用、实际输入和风险结果形成单向且可审计的作用链；Result 2 与 Result 3 的样本职责不再混用。
2. **实验完整性**：补齐四格操作定义、独立重复单位、冻结数据划分、命名随机流、物理连通审计、负对照、缺失结局和失败运行处理；最终阈值与样本量仍留待校准后冻结。
3. **观点主线**：全文统一为“识别信息介导的非最近邻风险效应，再在证据成立后优化安全约束控制”；Stage II 不用于反证 Stage I，控制收益也不替代因果识别。
4. **符号合理性**：区分请求命令与实际输入，区分候选消息与已采用消息，区分运行完整性与机制状态；消除预测编号、目标车辆索引和 jerk 的冲突，并统一 CVaR 与评估分布定义。
5. **前后衔接**：System model 提供共同对象，Stage I 定义识别问题，Stage II 定义控制问题，指标小节展开四类代价，实验设计和统计小节给出执行与推断规则，Results 仅保留证据职责。
6. **通俗易懂性**：保留必要数学约束，同时在 P1、P2、时间判定、Pareto 和 CVaR 后给出直接解释；删除重复定义和内部实验代号，避免把工程说明写成研究结论。
