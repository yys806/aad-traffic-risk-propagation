## 1. 结论先行

当前项目已经完成了风险事件提取、局部物理传播基线、消息协议原型、物理断开四格识别和合流迁移等一系列工作，并非“没有实验”。但按 NC 主张强度判断，现有证据仍不足以支持“信息介导的非最近邻风险效应是一种具有一般性的交通机制”。主要问题不是简单的运行次数少，而是证据结构不完整：

1. 最关键的双走廊和合流正式实验只有项目记录，当前 AAD 仓库没有 runner、配置、测试和原始输出，无法独立复算。
2. Pilot A 只有1个种子，Pilot B 只有2个种子；二者主要证明消息状态机和控制采用能运行，不能承担主效应结论。
3. 双走廊记录中的20/20同号和极窄区间来自高度受控场景。若没有场景异质性、强基线和独立重做，这种“过于整齐”的结果容易被解释为控制规则直接写入了预期答案。
4. 当前只有透明规则控制器、制动/TTC 风险、双走廊和单一合流几何；跨控制器、跨风险类型、跨交通需求和跨信息拓扑尚未完成。
5. 真实数据目前只完成测量字段审计或小样本轨迹计算，尚未观察到“消息生成—接收—采用—动作—风险”的现实闭环。
6. TTC 是主要风险指标，但尚缺 DRAC、PET/冲突指标、碰撞/近失事件、舒适性、效率、排放和误报警代价构成的多指标证据。

因此，旧实验应被重新分层：局部传播基线和失败批次保留；Pilot A/B 降级为工程原型；双走廊和合流结果必须从统一版本重做；跨控制器、跨风险、通信剂量、外部数据和混合现实闭环需要新增。仅“把20个种子扩到200个”不会自动达到 NC 标准。

## 2. 如何理解“NC 标准”

NC 没有规定交通仿真必须使用多少随机种子、多少城市或多少场景。官方要求是高质量、对相应研究共同体有意义的原创研究，并要求支撑主张的最小数据集、核心代码和协议能够被验证与扩展。因此，本路线图中的“NC 标准”是从相关 NC 论文归纳出的证据架构，而不是虚构的固定数量门槛。

代表性论文呈现出六个稳定特征：

- 一个清晰、可证伪的核心机制或识别问题；
- 受控系统中的决定性检验，而非只报相关性；
- 竞争基线、负对照和逐机制消融；
- 跨场景、跨模型、跨日期或跨网络的外部效度；
- 不确定性、失败结果、敏感性和实际代价；
- 可供审稿和复算的代码、数据、Source Data 与协议。

本项目最合适的证据链是：

`操作定义与测量验证 → 断开拓扑因果识别 → 消息生命周期和证伪 → 连通交通迁移 → 跨控制器/风险/拓扑一般性 → 真实数据与混合现实闭环`

### 3.3 旧实验中真正值得保留的部分

1. 物理传播基线已经有事件级数据、置换 null 和阈值敏感性，是 Result 1/5 的可靠基础。
2. Pilot B 的修复历史和消息生命周期字段对 Result 3 很有价值，因为它揭示了渗透率解析、跨运行状态污染和时序错位等真实失败模式。
3. 合流 v1 的失败不是负资产。它证明停止规则和资格门槛能否决不合格批次，应作为透明失败账本进入补充材料。
4. 真实数据审计清楚区分“轨迹风险”“接收远车状态”“逐包通信”“控制采用”，避免把不可观测层级写成现实闭环验证。

### 3.4 当前最危险的四种误读

1. 把“采用次数多”写成“风险收益大”。闭环轨迹分化后，消息机会数本身就是处理后变量。
2. 把“源—目标无直接边”写成“没有物理传播”。必须审计完整时序可达路径和最早物理到达。
3. 把“20/20为负”写成普适性。高度确定的人工场景只说明该实现稳定，不说明跨控制器、风险和交通分布成立。
4. 把真实轨迹 TTC 或 SPMD 接收记录写成真实采用因果效应。没有 adoption 和动作日志时，这一层不可识别。

## 5. 五类审稿人的综合判断

### 5.1 因果识别审稿人

会接受四格交互和时间顺序作为起点，但会追问：通道开启是否改变计算负载或其他控制路径；风险消息是否只是硬编码的提前刹车指令；共同触发机制是否同时制造源风险和目标风险；排除资格是否使用了处理后信息。必须加入 sham channel、随机消息、action-matched 和 outcome-blind qualification。

### 5.2 交通安全与仿真审稿人

会认为单一 TTC 和单一几何过窄。需要多驾驶模型、时间步、需求水平、风险类型和安全替代指标；必须报告风险下降是否以急刹、jerk、拥堵、排放或误报警为代价，并校准仿真风险分布与真实数据。

### 5.3 车联网与控制审稿人

会要求消息从生成到采用的全生命周期，以及时延、抖动、随机/突发丢包、更新率、消息老化、渗透率和多跳转发的剂量—响应。还会要求至少一个原理不同的控制器，证明效应不是透明规则的特例。

### 5.4 统计与复现审稿人

会拒绝把仿真帧、消息或车辆步当成独立样本。独立单位应是预先定义的 seed×scenario 配对或现实事件/行程；需要效应量、聚类区间、功效/精度设计、多重比较控制、失败分母、等效检验和完全可复算的 artifact。

### 5.5 NC 编辑

最可能问的不是“跑了多少次”，而是：除人工双走廊外，这一发现是否改变了我们对联网交通风险传播的理解？若只有规则控制器提前刹车，贡献会被降格为工程能力证明。要保住 NC 定位，必须证明一个具有预测力的机制：何时远端信息有益、何时无效或有害，以及这种边界能否跨控制器、风险和现实交通条件复现。

## 7. 新实验总纲

### 7.1 所有正式实验共用规则

1. 先冻结代码 commit、环境、配置 schema、种子表、主要终点、SESOI、失败规则和统计脚本，再运行正式数据。
2. 开发/功效 pilot 与正式 confirmatory seed 完全分离；正式种子从预先保存的哈希列表取得。
3. 主要统计单位是 seed×scenario 的四格配对，不把仿真步、消息或同一 trial 内多车当独立重复。
4. 主结局只设一个：归一化的 `I_TTC` 或经 E01 验证后的风险负担。其他安全指标为关键次要结局。
5. 样本量先用30个独立 pilot seed/层估计配对方差，再以90%功效检测预设最小实际效应，并要求95%区间半宽不大于0.2×SESOI。正式主层每层不少于100个配对 seed；若功效计算给出更大值，采用更大值。
6. 负对照不只做“未显著”，而做等效检验：其95%区间必须完全位于预设零效应带内。
7. 所有碰撞、超出动力学限制、源事件未形成、未交付、未采用和动作未分化均保留在总分母并分类报告；不得静默删除。
8. 主效应使用配对差分和分层模型；区间按 seed/scenario 聚类 bootstrap；同时给 exact/sign permutation。多项次要结局使用预设层级检验或 FDR。
9. 同时报绝对效应、相对效应、原始点、区间、SESOI、失败率和计算预算，不只报 p 值。

### 7.2 E00：可复现性恢复与统一重建（投稿阻断项）

目标：让所有核心结果从当前 AAD 仓库的一条命令重算。

- 在 `code/` 内重建双走廊、合流、消息生命周期、统计与绘图入口；不从历史摘要反向伪造原始数据。
- 每个 run 输出 frozen config、Git commit、环境、SUMO版本、随机种子、开始/结束时间、退出码、state、emission、protocol、risk 和 audit。
- 生成 manifest、SHA-256、失败账本和一条只读分析命令。
- 建立最小测试：四格唯一差异、时间对齐、跨 run 状态隔离、车辆 ID 生命周期、消息单调时序、路径判定、统计结果复算。
- 由第二个干净环境独立复算至少一套主实验；最好由未参与实现的人执行。

通过标准：删除全部缓存后可复算论文表格；关键数字可追溯到 run-level 文件；旧双走廊/合流数字若不能恢复则标记为历史记录，不纳入新统计。

### 7.3 E01：风险指标、物理路径与仿真数值验证（Result 1）

目标：证明测量对象有效，而不是先假定 TTC 积分可靠。

- 在人工可解析轨迹上验证 TTC、`I_TTC`、DRAC、modified TTC、PET（交叉/合流）和碰撞判定。
- 对 SUMO step length 0.1/0.05/0.02 s 做收敛；检查领导车切换、负间距、停驶、瞬时加速度和插值误差。
- 物理到达算法用手工构造的有路径、无路径、时变路径、右删失和多路径图单元测试。
- 用 NGSIM/INTERACTION 事件分布校准仿真中的 TTC、相对速度、减速度和事件持续时间；极端值人工审计抽样。
- 比较帧级与事件级统计，冻结 episode 合并规则，避免伪重复。

通过标准：不同时间步下主指标差异小于预设容差；人工轨迹和路径真值全部通过；主要结论对至少两个独立风险指标同方向。

### 7.4 E02：物理断开主四格确认实验（Result 2，核心）

设计：`S∈{0,1} × C∈{0,1}` 四格，源—目标道路结构完全断开，指定消息为唯一跨走廊信息。

分层因素：

- 3档目标基础风险（低/中/高，但均有可测范围）；
- 3档交通需求；
- 3档源—目标相对事件时间；
- 2种人驾参数分布；
- 至少3个目标位置/前车组合。

以场景分层抽样而非全笛卡尔堆量。每个主要层采用 `max(100, 功效所需N)` 个正式配对 seed；固定留出20%的场景族只做一次最终验证。

主要终点：配对 `Delta_NL` 的归一化风险负担。关键门槛：四格完成、处理前一致、零物理时序路径、C=0零采用、S=0无源消息、消息先于动作、碰撞/动力学约束合格。

必须报告：四格原始分布、每个 seed 效应、异质性、零/正效应、实际等效边界、拓扑证明和失败分母。

### 7.5 E03：强竞争基线与“并非只会提前刹车”检验（Result 2/4）

至少比较：

1. local-only 基础控制器；
2. local predictive controller（只用本地历史预测）；
3. always-cautious/固定提前减速；
4. oracle risk state（理想上界）；
5. remote raw-state message；
6. remote risk-summary message（本文方法）；
7. action-matched control：不接收消息，但重放相同动作时序；
8. bandwidth/computation-matched sham channel。

核心判断：本文消息应在相同安全收益下比 always-cautious 具有更低效率/舒适性代价，并相对 local predictor 提供增量信息；否则结论只是“提前保守驾驶可降低 TTC 风险”。

### 7.6 E04：独立实现与复现实验（Result 2）

目标：排除主效应由单一 runner、统计脚本或消息实现的隐蔽缺陷造成。

- 用独立脚本从原始 state/protocol 重算四格效应，不调用在线汇总器。
- 为关键四格建立一个最小第二实现：可采用另一仿真封装、另一控制接口或同一 SUMO 网络的独立 runner，但不得复制主实现的状态机代码。
- 独立实现共享冻结场景和 estimand，不共享结果缓存；比较方向、效应量和失败分类。
- 对历史出现过的时间错位、state 污染、车辆 ID 陈旧和错误路径匹配逐项做 mutation/regression test。

若第二实现不能复现，主效应停留在软件验证阶段，不进入科学解释。

### 7.7 E05：消息生命周期与正式中介链（Result 3）

逐 trial 重建：event → generation → send → drop/delay → delivery → source/freshness validation → adoption → action divergence → risk divergence。

- 报告每一级转化率和时间分布，不只报总采用次数。
- 对每个失败 trial 指明链条断点。
- 用分层中介/机制分解作辅助分析，但因处理后中介存在假设，不替代四格主估计。
- 加入双实现核验：在线日志与离线从 state/protocol 重建的时间必须一致。

### 7.8 E06：完整负对照和证伪矩阵（Result 3）

| 负对照 | 应停止的环节 | 预期 |
|---|---|---|
| wrong-source | 来源校验 | 交付可有，采用为0，效应等效于0 |
| wrong-target | 目标校验 | 采用为0 |
| wrong-time/future timestamp | 时序校验 | 采用为0 |
| expired/stale | 新鲜度校验 | 采用为0 |
| delivery-only | 控制入口 | 有交付、无采用、效应等效于0 |
| random payload | 语义/动作映射 | 无系统效应 |
| pseudo-source with matched rate | 来源与共同时间趋势 | 无系统效应 |
| S=0 channel-on | 通道运行本身 | 无系统效应 |
| shuffled event–message pairing | 事件特异性 | 无系统效应 |
| message after physical arrival | 时间竞争 | 不得解释为非局部信息先行 |

每类负对照至少50个配对 seed，并用等效检验确认落入零效应带；若任何负对照出现稳定同方向效应，主机制暂缓解释。

### 7.9 E07：通信剂量—响应与失效边界（Result 3/6）

因素：固定时延、随机时延、抖动、独立丢包、Gilbert–Elliott 突发丢包、更新率、消息年龄、通信范围、渗透率、转发跳数和拥塞负载。

建议档位：

- 时延：0/20/50/100/200/500 ms；
- 丢包：0/5/10/20/40/60%；
- 更新率：1/2/5/10 Hz；
- 渗透率：0/10/20/40/60/80/100%；
- 老化上限：0.1/0.3/0.5/1/2 s；
- 跳数：0/1/2/3及以上。

采用空间填充/正交设计筛选关键交互，再对转折区加密，不必全笛卡尔积。输出风险—通信—效率 Pareto 面、失效阈值和非单调机制日志。

### 7.10 E08：逐模块消融（Result 3/6）

分别移除或替换：来源验证、新鲜度门控、事件资格、采用策略、风险强度编码、动作映射、安全盾、消息聚合、多源冲突解决、本地/远端融合和路径时序检查。

要求每项消融跨双走廊、合流和至少一个留出风险场景；报告风险、误报警、jerk、效率、碰撞和链条失败。不能只做神经网络层消融而忽略协议语义消融。

### 7.11 E09：多合流几何迁移（Result 4）

至少覆盖：短/中/长加速车道、不同汇入角度/限速、单车道与多车道、不同主线需求、不同汇入需求和不同目标位置。每一场景族先用与 outcome 无关的源事件条件资格化，再锁定全新正式种子。

- 保留 v1 失败作为独立批次；新实验不得覆盖或合并。
- 每个主要几何 `max(100, 功效所需N)` 个四格配对。
- 报告 `t_adopt`、`t_action`、经验 `tau_P` 及不确定性；结果窗口必须在物理到达前。
- 对右删失 `tau_P` 使用生存/区间方法，不把“未观察到”写成“无限远”。
- 同时报 TTC/DRAC/PET、碰撞、硬刹、jerk、速度、吞吐、旅行时间、排放与队列外溢。

### 7.12 E10：时间竞争的独立验证（Result 4）

- 用消息屏蔽 counterfactual、冲击响应和时序可达图三种方法估计物理到达。
- 人工注入已知传播速度的校准扰动，验证 `tau_P` 估计误差。
- 画全部 trial 的 `source→message→adoption→action→physical arrival→outcome window` 时间轴。
- 进行窗口起点、长度和动作容差敏感性；主结论不得依赖单个任意容差。
- 将 `t_action≥tau_P` 的 trial 明确分类为“不可归因”，而不是负效应或零效应。

### 7.13 E11：跨控制器复现（Result 6，投稿关键）

至少三类原理不同的目标控制器：

1. 当前透明规则控制器；
2. 带安全约束的 MPC/CBF-MPC；
3. 经过冻结训练的学习控制器（SAC/PPO 或离线策略），外加独立安全盾。

所有控制器接收相同消息语义和本地观测，分别调到可比的无消息基线安全/效率，再运行同一四格协议。学习控制器至少5个独立训练 seed，评估 seed 与训练 seed 分离；不得只挑最佳 checkpoint。GPU 主要用于此项和 E19，而不是用于普通 SUMO 重复。

通过标准：至少两个原理不同的控制器在预设方向上复现主效应，且异质性可解释；若只有规则控制器成立，应把论文主张收缩为特定控制协议。

### 7.14 E12：跨风险类型（Result 6）

至少覆盖：

- 前车急刹/追尾风险；
- cut-in/lane-change 冲突；
- 合流让行冲突；
- 瓶颈/队列尾部冲击；
- 可选：交叉口不让行或侧向侵入。

每类风险使用适配指标：追尾用 TTC/DRAC，交叉/合流用 PET 或冲突时间，网络扰动用队列/传播负担。统一报告标准化效应，不把不相容的原始 TTC 数直接平均。至少保留一个完全未参与设计调优的风险类型作预测性留出检验。

### 7.15 E13：跨拓扑、需求和驾驶行为（Result 6）

- 信息图：单源、冗余多源、冲突多源、星形、链式、多跳、社区/motif 和动态断连。
- 物理图：断开、串行跟驰、合流、瓶颈、环路/网格局部网络。
- 交通：自由流、临界、拥堵；需求波动；CAV penetration；不同人驾模型与参数分布。
- 驾驶模型：至少 Krauss/IDM(EIDM) 与一种独立跟驰模型；用现实轨迹分布校准而非手工挑参数。

目标不是证明“处处有效”，而是学习可解释的适用域与失效域，并预先提出预测：信息领先裕度、消息新鲜度、目标风险可控余量和物理传播速度共同决定收益。

### 7.16 E14：第二阶段安全约束控制优化（Result 4/6）

只有 E02–E10 证明因果链后才进入。本阶段比较规则、MPC/CBF-MPC 和学习策略在风险—舒适—效率多目标下的 Pareto 前沿。

- 训练目标不得只最小化 TTC；加入碰撞硬约束、jerk、旅行时间、吞吐、排放和误报警响应。
- 与 always-cautious 和 oracle 上界比较。
- 做 distribution shift、传感噪声、通信异常、控制饱和和故障恢复。
- 报告最坏5%/1%尾部风险，而不只报均值。

### 7.17 E15–E17：真实数据外部锚定（Result 5）

E15 轨迹：完整处理 NGSIM 多地点/时段、pNEUMA 地图匹配和 INTERACTION 多场景；统一前车匹配、episode、TTC/DRAC/PET 和不确定性规则。以事件/车辆/场景分层，不把帧当独立样本。

E16 通信：在 SPMD 中完成 Packet、发送侧 BSM 与 `RV_RX` 配对，得到机会条件下的时延、丢包、连续性和距离分布；不能观察 adoption 时明确停在接收层。

E17 分布匹配：比较真实与仿真的速度、间距、相对速度、减速度、风险持续时间、需求和通信条件；使用 calibration/validation 分割，给出仿真覆盖真实分布的范围和不覆盖区。

通过标准：现实数据至少能独立支持风险测量、物理传播背景和通信可达性三层；不得将三层拼接为并未观测的单车闭环因果链。

### 7.18 E18：硬件在环/同步混合现实闭环（NC 高价值项）

若无法获得带 adoption 日志的真实道路数据，建议搭建 CARLA/SUMO/Autoware 或实车控制器在环：

- 真实控制栈接收仿真远端风险消息；记录生成、网络、采用、控制命令和车辆/动力学响应。
- 注入实测级时延、抖动、突发丢包、传感噪声和控制执行延迟。
- 覆盖急刹、cut-in、合流和误报警；与 local-only、always-cautious、oracle 比较。
- 若有封闭场地条件，使用低速代理车辆/实车做安全边界内验证；否则明确为 HIL，不称道路实证。

该项不是形式要求，但对一个以“显式信息采用改变风险”为核心的论文，它能显著缩短从纯 SUMO 机制到真实控制闭环的证据距离。

### 7.19 E19：对抗稀有事件与尾部可靠性（Result 6）

使用 GPU 训练场景生成器或重要性采样器，主动寻找当前控制器的失败条件：极端 cut-in、突然急刹、多源冲突消息、低附着/长延迟组合和高密度交通。生成器必须受现实分布或动力学约束，避免无意义的不可实现对抗。

- 将发现的场景冻结为独立 stress-test suite；不能在同一批场景上训练后宣称泛化。
- 报告碰撞/近失率、CVaR 或最坏分位、失败模式覆盖率和与自然分布的权重校正。
- 所有失败场景进入公开 failure zoo，作为方法边界而不是删除项。

## 8. 指标体系

### 8.1 主要终点

- 一个预先冻结、经 E01 验证的目标车辆事件级风险负担；建议保留 `I_TTC`，但必须给出归一化定义和实际意义阈值。

### 8.2 关键次要安全指标

- TTC/modified TTC；
- DRAC；
- PET（适用于交叉/合流）；
- 冲突持续时间与严重度；
- 碰撞、近失、硬刹率；
- 最坏1%/5%风险和 CVaR。

### 8.3 代价与副作用

- jerk、加速度变化、控制饱和；
- 平均速度、旅行时间、吞吐、队列长度/外溢；
- 能耗/排放；
- 误报警率、不必要采用率、通信负载；
- 不同车辆/位置的收益分布，避免收益只集中在指定目标。

## 9. 统计分析计划

1. 主估计量：四格配对交互 `Delta_NL`，按 seed/scenario 层级建模。
2. 主分析：分层线性/广义混合模型或对应稳健模型，scenario family 为固定效应，seed/geometry 为随机效应；保留配对结构。
3. 区间：cluster bootstrap 或 Bayesian hierarchical interval；同时报告配对 permutation/sign test 作为少假设核验。
4. 稀有碰撞：使用二项/Poisson 率模型和暴露量，不以“0碰撞”证明安全；给零事件上限。
5. 等效与非劣：负对照用 TOST/区间等效；效率和舒适性用预设非劣界；主效应用 SESOI 而非只看零点。
6. 多重比较：主终点单一；关键次要终点按层级顺序；探索性矩阵采用 BH-FDR，并明确标注探索性。
7. 缺失与失败：以意向运行集为主，另报机制合格集；任何 post-treatment 排除仅作敏感性分析。
8. 稳健性：不同容差、窗口、风险阈值、时间步、驾驶模型和异常处理规则；展示 specification curve。
9. 泛化：预先冻结留出场景/种子，只在所有开发决定结束后解锁一次。

## 10. 计算与工程资源

| 工作 | 主要资源 | 说明 |
|---|---|---|
| SUMO 四格、通信和几何矩阵 | 多核 CPU | 高并发比 GPU 更重要；每 run 单独进程和状态 |
| MPC/CBF 控制 | CPU，可选 GPU | 重点是求解时延和闭环稳定性 |
| SAC/PPO、多策略训练 | GPU + CPU rollout | 至少5训练 seed；保存全 checkpoint/曲线 |
| 对抗场景生成/重要性采样 | GPU + 大量 CPU 仿真 | 训练集、开发集、冻结 stress test 分离 |
| 真实轨迹/通信全量处理 | 大内存 CPU/高速存储 | 流式解析、分区 Parquet、checksum |
| HIL/混合现实 | 独立控制机+网络仿真 | 记录端到端延迟和实际执行命令 |

## 11. 推荐推进顺序与门槛

### Gate 0：可复算

完成 E00、E01。若当前版本不能稳定生成同一 run-level 统计，不启动大矩阵。

### Gate 1：决定性识别

完成 E02、E03、E04、E05、E06。若独立实现不能复现、强基线消除效应，或任何负对照不等效于0，则先修正主张和机制，不进入“泛化堆量”。

### Gate 2：连通迁移

完成 E09、E10。若信息领先窗口在大多数合流 trial 不成立，Result 4 改写为失败边界，不用筛种子补成正结果。

### Gate 3：一般性

完成 E07、E08、E11、E12、E13。至少两个控制器、三个风险类和多交通/信息拓扑形成可解释的作用边界。

### Gate 4：现实锚定

完成 E15–E17；优先完成 E18。现实层级分别陈述，不跨越不可观测 adoption。

### Gate 5：高影响增强

完成 E14、E19，把机制转化为安全约束控制价值和稀有尾部可靠性。

## 12. 最小 NC 投稿包与满配 NC 投稿包

### 12.1 最小但可信的 NC 投稿包

- E00–E04：可复算、测量验证、断开主效应、强基线和独立复现；
- E05–E10：完整机制、负对照、通信剂量、消融、合流和时间竞争；
- E11–E13：至少两类控制器、三类风险、多拓扑/需求；
- E15–E17：全量现实测量/通信锚定；
- 全部代码、最小数据、配置、Source Data、失败账本和 DOI 归档。

### 12.2 冲击力更强的满配包

在上述基础上增加 E18 混合现实/封闭场地闭环、E19 对抗稀有事件和 E14 多目标安全控制。这三项比把同一 SUMO 人工场景从100 seed扩到1000 seed更能提高论文等级。

## 13. 立即停止做的“无效堆量”

- 不恢复原始包就围绕历史均值继续画图或写显著性。
- 在同一确定性双走廊只增加 seed，却不增加可影响效应的异质性。
- 把消息、帧和 vehicle-step 当独立样本制造极小 p 值。
- 只和 no-control 比，不和 local predictor、always-cautious、oracle 和 action-matched 比。
- 为得到正结果反复改风险窗口、阈值、目标车辆或资格种子。
- 用0碰撞宣称安全，而不报暴露量和零事件上置信界。
- 将 NGSIM TTC、SPMD 接收记录和仿真 adoption 拼成一个现实因果链。
- 用 GPU 训练复杂模型却不做留出验证、消融和实际控制约束。

## 15. 最终判断

当前证据足以支持“这是一个值得继续的可证伪机制研究方向”，但不足以支持 NC 稿件中的一般性机制结论。最优策略不是删除失败实验或立即训练一个更大的神经网络，而是先把最强的因果识别链做成不可挑剔的、可复算的主结果，再用跨控制器、跨风险、真实数据和混合现实逐层扩大外部效度。

如果 E02 的效应在强基线下仍成立、E06 负对照全部等效于零、E09 在多合流几何中满足信息先行、E11–E13 给出可预测的一般性边界，并且 E15–E18 至少建立现实测量与闭环控制锚点，那么该项目才真正具备以“信息网络改变交通风险传播机制”冲击 NC 的实验基础。
