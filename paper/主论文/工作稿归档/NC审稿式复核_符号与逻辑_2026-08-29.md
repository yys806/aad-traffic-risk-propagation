# 主论文 NC 审稿式复核：符号、逻辑与投稿结构

**复核日期：** 2026-08-29  
**复核对象：** `paper/主论文/main.tex`  
**复核范围：** 导师符号要求、符号首次定义与唯一性、区域级效应与单车审计的衔接、P1/P2 数学闭合、Introduction–Methods–Results–Discussion 逻辑、Nature Communications 投稿结构。

## 结论

不能声称“已经全部按照导师要求且达到 NC 投稿完成状态”。导师要求的主要符号替换已经落实，当前文件可编译且没有未解析交叉引用；但仍有四类需要作者确认后才能修改的审稿级问题：

1. **区域级核心效应与单车级时间约束没有完全闭合。** 主要终点是目标区域总体风险 $R_{\mathcal R^{\mathsf T},\omega}$，但 P1 的物理可达性、消息采用和动作分化约束只对未量化的单个 $v$、$v'$ 和 $q$ 写出。需要明确“区域级信息先行”是对所有合格目标车辆成立，还是以目标车辆中最早物理到达边界定义区域边界。按当前主张，较稳妥的数学表达是对 $v\in\mathcal V^{\mathsf T}_\omega$ 全称量化，并定义区域边界为 $\tau_{\mathcal R^{\mathsf T},\omega}^{\mathsf P}=\min_{v\in\mathcal V^{\mathsf T}_\omega}\tau_v^{\mathsf P}$，否则审稿人可能认为区域结果由单车机制证据支撑不足。

2. **Stage II 的动作代价存在自由索引。** `J_{\omega}^{\mathsf{act}}`（约 423–425 行）分子和分母使用 $v$，但没有对目标车辆求和、平均或加权，因而数学上仍是一个未指定车辆的代价，不能直接称作运行级总体代价。必须确定区域级聚合规则：目标车辆等权平均、总和，或按暴露时间/车辆权重聚合。

3. **Stage II 的效率代价没有说明区域聚合层级。** `T_{\omega}^{\mathsf{obs}}$、$T_{\omega}^{\mathsf{stop}}$、$\bar{\mathbbm v}_{\omega}$`（约 429–443 行）没有车辆索引，也没有定义为目标车辆集合的平均、总和或其他区域聚合量。当前正文同时声称约束目标区域的效率代价，因此需要补充统一聚合规则，并说明目标车辆数量变化如何处理。

4. **P2 约束的全称量化不完整。** 动力学、请求命令、硬安全和部分消息约束（约 321–355 行）没有统一写明对哪些 $v$、哪些时间步 $t$、哪些消息 $q$ 成立。虽然部分行已有 `\forall t`，但没有覆盖车辆集合；严格审稿时会被理解为只对一个自由车辆索引成立。应在 P2 公式前或各约束中统一声明量化域。

## 已落实的导师符号要求

- 车辆集合使用 `\mathcal V=\{v_1,\ldots,v_{|\mathcal V|}\}`，并以 $v$、$v'$ 作为车辆实例索引。
- 全体状态使用粗体 `\bm S_t`，实际输入集合使用粗体 `\bm X_t`，消息状态集合使用粗体 `\bm M_t`。
- 单车状态写作 `\bm s_{v,t}=(\mathbbm p,\mathbbm v,\mathbbm a,\mathbbm\ell)`；请求输入和实际输入区分为 `\bm x_{v,t}^{\mathsf{cmd}}` 与 `\bm x_{v,t}^{\mathsf{act}}`。
- 网络、区域、事件、风险和策略语义标签位于上标，车辆、消息、运行和时间索引位于下标。
- Stage I 处理变量使用 `\mathsf{scr}` 与 `\mathsf{opn}`，没有发现旧的 $S,C$ 处理写法。
- 消息状态统一为 `D^{\mathsf{del}}`、`Q^{\mathsf{chk}}` 和 `Z^{\mathsf{adopt}}`。
- 未发现旧的 `i_s`、旧的 `R_{j,\omega}`、`风险负担`、`DRIFT` 或 `AAD` 残留。
- “类超距作用”的非量子、非超光速、非无媒介限定已放入脚注；Introduction 的核心对象已经改为目标区域总体风险。

上述结果说明**符号刷写的表面层基本完成**，但 `v`（车辆索引）与 `\mathbbm v`（速度）视觉相近，后续仍需保持全文严格一致，不能再引入另一套车辆索引或速度记号。

## 需要确认后修改的数学问题

### P1：识别问题与区域级时间边界

- `\mathcal P_1` 同时写“估计 $\Delta^{\mathsf{NL}}$”和两个判定主张 `\mathsf{NLE}^{\mathsf{exist}}`、`\mathsf{NLE}^{\mathsf{safe}}`。这不是错误，但估计目标与确认性判定的层级略混；可保留为联合定义，也可将判定条件移到统计分析小节。
- 约束 (11b)、(11d)–(11m) 中的 $v'$、$v$、$q$、$\omega$ 和时间域没有全部显式量化。
- 当前 (11b) 对一条未指定的源–目标车辆路径写 `Reach=0`，与区域总体风险主张不完全对应。需要在“所有合格目标车辆”与“区域最早物理到达边界”两种方案中选择一种并全文统一。
- 当前信息先行条件对单车写出两条时间不等式，但没有给出区域风险窗口整体通过的聚合判据。若保留区域总体风险为主要终点，建议在修改方案中明确区域级判定，再将单车时间量作为组成审计。
- `\mathcal M_\omega^{\mathsf{src}}` 的定义文字同时包含源车和目标车，但 P1 主约束只要求存在一条已采用消息；若区域级效应要求多车共同响应，需要说明是“至少一辆”还是“每一名合格目标车至少一条”。

### P2：策略、代价与约束闭合

- `J_{\omega}^{\mathsf{risk}}` 已在 TTC 小节按目标车辆集合求和；`J_{\omega}^{\mathsf{act}}` 和 `J_{\omega}^{\mathsf{eff}}` 尚未采用同一层级的聚合，造成三类运行级代价的定义不对称。
- `J^{\mathsf{tail}}` 对运行级风险代价做 CVaR，逻辑上成立，但应在最终稿明确风险代价是否为总和、均值或按区域暴露加权，否则 CVaR 的解释会随目标车辆数量变化。
- P2 的策略输出 `Z_{q,v}^{\mathsf{adopt}}(t)` 与前文“消息采用状态”的记录含义一致，但需要明确它是观测状态、策略决策还是二者在运行器中的同一字段。
- P2-(a)–(j) 的车辆和时间量化域需要统一；P2-(f)–(h) 的 $q$ 还应限定在候选或合格消息集合中，以避免对不存在的消息施加约束。

## Introduction–Methods–Results–Discussion 一致性

### 已一致

- Introduction 将核心对象限定为“来源可追溯的远端风险信息对目标区域总体风险的增量效应”，并把研究拆为 Stage I 识别和 Stage II 控制。
- Results 1–6 目前只写职责边界，没有把未获得的数值伪装成结果；Result 2 对应区域级核心效应，Result 3 对应作用链，Result 4 对应物理连通场景和控制价值，Result 5 对应真实数据外部校核，Result 6 对应适用域与失效边界。
- Methods 明确规定规则和复现条件，且在末段明确 Results 报告验证结果，避免把实验结果混入方法定义。

### 仍需注意

- Introduction 的 (i)–(vi) 是全文研究环节顺序，不是单次运行内部时间顺序；Methods 已有说明，但 Results 标题和正文后续填充时必须保持这一边界。
- Stage II 只能在 Stage I 达到预设门槛后启动，且不能反过来证明 Stage I；当前 Introduction、System model 和 Stage II 段落一致。
- P1 的核心风险符号 $R$ 与 P2/指标小节的运行级代价 $J^{\mathsf{risk}}$ 已有文字映射，但还需要在最终修改中明确“同一风险测量、不同处理/策略索引”，否则容易被读成两套风险定义。
- 目标车辆集合在处理前确定，但其数量和结果窗口内有效观测量可能跨运行变化；这会影响“区域总体风险”的总和解释和场景间比较，必须在聚合规则中固定。

## NC 投稿格式检查

- 当前标题、摘要、Introduction、Results、Discussion、Methods、Data availability、Code availability、References 和投稿后声明区块的顺序是合理的。
- Introduction 和 Discussion 没有子标题，符合 NC 常见结构。
- 当前 Results 和 Methods 使用 `\subsection*`。项目内 NC 指南要求 Results 和 Methods 使用不编号的一级小标题、不设二级小标题；因此，若严格按该指南，后续应将这些标题改为 `\section*` 或采用等价的一级标题层级。这是格式问题，需要作者确认是否现在处理。
- 摘要、Acknowledgements、Author contributions、Competing interests、Figure legends 和 Tables 仍为空或占位；因此当前稿可交老师审阅理论框架，但不能称为最终可投稿稿。
- Data availability 和 Code availability 仍使用“将在发表时”“对应版本将……”的未来时态；正式提交前应改为与实际归档、代码标签和数据访问状态一致的事实陈述。
- 参考文献当前嵌入 `main.tex`，但仍保留外部 `references.bib` 作为迭代文件；正式英文投稿前需按期刊当时要求确认是否需要将 `.bbl` 内容嵌入单一 `.tex` 文件。
