## 核心发现：Word 的 pt 与 PDF 的 pt 不是同一个 pt

这是过去「怎么调都差一点、一页累积错位 50pt」的头号根因：

- TeX 的 `1pt` = 1/72.27 英寸；PDF/Word 的 `1pt`（即 `bp`）= 1/72 英寸。
- 于是 `\baselineskip=23.4pt` 渲染出来只有 **23.31bp**，每行少 0.09，十行差 0.9，一页差好几 pt。
- **所有从官方 .doc / 官方 PDF 量出来的数值，一律写成 `bp` 单位**（cls 里已是 `23.4bp`、`18bp`、`25.35bp`）。
  自己按 PDF 实测拟合出来的坐标（封面、审核框外定位）本来就是 PDF 口径，保持 pt 不动。

## 正文版式引擎：按 Word 的规则算，不按坐标凑

LaTeX 的行距是「基线到基线」，Word 的行距是「行盒高 + 段后 + 段前」，两者在字号变化处必然分叉。
所以正文不再一处一处调 `\vspace`，而是把 Word 的规则直接写进 cls：

    本段首行基线 = 上一段末行基线 + 上一段行高 + 上一段段后 + 本段段前

行高与段前后全部取自官方 .doc 的段落属性；每个宏把自己用到的值记进 `\tj@lastH` / `\tj@lastAfter`
供下一段查询。**加字、删段、改字号都不会让版式跑偏，不需要重新对坐标**——这是「原生一致」的意思。

| 段落类型 | 行高 | 段前 / 段后 |
|---|---|---|
| 一级标题 一、四、 | 18bp（固定值 18） | 6 / 6 |
| 一级标题 二、三、 | 25.35bp（1.5 倍） | 6 / 6 |
| 二级标题 | 23.4bp | 6 / 6 |
| 正文、空段 | 23.4bp | 0 / 0 |
| 9pt 说明 | 17.55bp | 0 / 0 |
| 提示语 | 23.4bp | 6 / 6 |
| 参考文献 | 23.4bp | 0 / 0 |

页首另外处理：Word 在新页第一行**保留**段前距，LaTeX 会连 `\vskip` 一起丢掉，所以引擎在页首
（判据 `\pagegoal=\maxdimen`）改为把偏移塞进首行行盒高度，实测 p2 首行 85.58 与官方完全相同。

### 四处「官方自己不一致」的地方

官方 .doc 里有几处段间距与它自己的段落属性对不上（Word 手工排版痕迹），引擎按属性算会差 1–5pt，
故用 `\tjformgap{…}` 显式覆盖，主文件里每处都注明了「官方实测值 / 属性算出值」：

| 位置 | 官方实测 | 属性算出 |
|---|---|---|
| 一、→说明 | 18.72bp | 24.00bp |
| 说明→1．选题 | 26.52bp | 23.55bp |
| 空段→二、 | 31.47bp | 29.40bp |
| 提示语→空段（3．前） | 26.64bp | 29.40bp |
| 空段→三、 | 28.68bp | 29.40bp |
| 空段→四、 | 24.50bp | 29.40bp |

同一类转移在官方原件里能差 2.8bp（如「空段→一级标题」在二、是 31.47、在三、是 28.68），
这不是本工程的误差，是原件本身不齐。

## 还剩的偏差（诚实记录）

1. **参考文献里的纯西文行**：Word 的行高按「该行出现过的最大字体」算，纯西文行用 Times 的 20.6–22.4bp，
   含汉字的行用宋体的 23.4bp；LaTeX 一段只能有一个 `\baselineskip`，取 23.4 后纯西文行每行多 1–2.8bp。
   后果：四条样例参考文献累计差 6.4bp，并让 p3 的「四、」低 0.83bp。换成真实中文文献后自然消失。
2. **封面信息表整体下移 7.4bp**：题目 21 字 × 14pt = 294bp，超过官方字段宽度 280bp，必然折两行
   （在 Word 里同样会折），故下方各行随之下移；日期行由 `\vfill` 锁在 702.96 不动。
   要比对「填了题目的封面」，需要把同样的题名填进官方 .doc 再导出 PDF 才能对——这一步还没做。

## 五个坑（都实测踩过，别再踩）

1. **`main.tex` 开头的 `\input@path` 不能删**。删了 TeX 找不到 `style/tongjithesis.cls`，报 `File 'tongjithesis.cls' not found`。
2. **`times=true` 必须开**。不开会回退到 TeX Gyre Termes，看着像 Times 但**不是同一个字体**，字体名一比就露。
   开它之后字体度量会变，`ctitlegap` 22.3 / `cbodygap` 98.0 是按开它之后重校过的，别照旧值调。
3. **封面大标题的括号是宋体，不是 Times**。官方 `.doc` 逐字符读过，`(` `)` 的 NameAscii 也是宋体；xeCJK 默认把 ASCII 括号码归西文字体，cls 里已用字符类声明单独处理。
4. **参考文献那段灰字是 12pt 宋体伪粗，不是 9pt 黑体**。模板把宋体 BoldFont 设成了 SimHei，直接 `\bfseries` 会变成黑体，cls 里用 AutoFakeBold 单独做，命令是 `\tjformrefnote`。
5. **`latexmkrc` 里不要限制编译轮数**。从零开始编需要三轮才稳定，限死两轮会报 `xelatex needed too many passes`（当初为 Overleaf 超时限制过，Overleaf 已不用了）。

### 排查陷阱一：首行缩进「测出来只有 18pt」是假象

以「【待写】」开头的段落，量 PDF 会看到首行 x0 = 107.95（左界 89.9 + **18.05**），像只缩进 1.5 字符。
**不是 bug**：`\parindent` 确实是 2em = 24.09pt，是 xeCJK 的**行首标点挤压**把全角「【」左移了约 6pt。
用普通汉字开头的段落实测 x0 = 113.86 = 89.86 + 24.0，正好 2 字符。**以后再看到 18pt 别去改 `\parindent`。**

### 排查陷阱二：页首的 `\vskip` 会被 TeX 丢掉

在页首插 `\vskip` 是无效的（页顶胶被丢弃），必须改判据并把偏移放进首行行盒高度（`\tj@ruleh`）。
2026-11-27 就是这里让 p2 首行低了 2.38bp，来回调三轮才发现。

## 参考文献怎么加、怎么引（2026-11-27 改）

**不再手写条目。** 条目全在 `refs.bib`（25 条，每条都有 DOI，来源经 CrossRef 核过作者、卷期页、文章号）。

- 正文引用写 `\cite{key}`，一句里要引几篇就连写几个 `\cite{}`，**不要写成一个方括号里的 1-3 或 1,2,3**：
  连写 `\cite{a}\cite{b}\cite{c}` 排出来是 上标 [1][2][3]。
- 编号、顺序、文献表内容全由 biber 现算，删一条或插一条都不用改正文。
- 参考文献格式由文档类的 `biblatex style=gb7714-2025` 出，标点半角、悬挂 0.74cm，与 Word 模板一致。
- DOI 在 PDF 里是真链接，能点开；正文里的 [n] 也能点，跳到文献表对应条目。

**编译顺序变了**（多一步 biber，`latexmkrc` 已经配好，直接 latexmk 就行）：

```
latexmk -xelatex main.tex          # 自动跑 xelatex → biber → xelatex ×2
```

编辑器里要选「XeLaTeX + Biber」，只选 XeLaTeX 会出现引用全是 [?]。

**新增文献**：先把 DOI 丢给 CrossRef 拉元数据（作者给首字母、`journal` 或 `booktitle`、`year/volume/number/pages`、`doi`），
写进 `refs.bib` 再加 `\cite`。不许凭记忆著录。
